# 0.6.2 发布验证

## 本地验证

- 在已合并最新 main（含 #47、#48）的源码上，用 ESP-IDF 5.5.2 从干净检出构建（提交 `774c3a97`）：版本 0.6.2，主固件 2,226,000 字节，3 MiB 分区剩余约 29%，无编译警告；构建不会改动任何已提交的文件。
- WebUI 静态与目录检查 133 项、真实浏览器回归 720 项通过，覆盖中英文失败提示 189 个场景、删除保护弹窗、规则配置包导入、SSH 指纹确认、密钥生成、LPMU 接入等；离线终端回归 4 项通过。
- `tests/runtime/run_all.sh` 44 项、规则包 8 项通过；WebSocket 四个入口、风扇输出与回落、证书回归（真实 MbedTLS 的 CSR、HTTPS 生命周期、证书接口、服务停止）、发布与 CI 策略检查通过。
- 构建产物检查：`www.bin` 与刷写映射一致，13 个成品资源的语法和 gzip 通过；加载真实成品 WebUI 的冒烟测试与缺资源负例通过。

## 默认刷机镜像

仓库 `build/` 下的 `TianShanOS.bin`、`www.bin`、`bootloader/bootloader.bin`、`partition_table/partition-table.bin`、`ota_data_initial.bin` 和刷写映射 `flasher_args.json` 来自同一次干净构建（提交 `774c3a97`），版本和 SHA-256 见 `build/firmware-manifest.json`。

每次发版的更新方法：在被构建提交的干净检出上用 ESP-IDF 构建，然后运行 `python3 tools/make_firmware_manifest.py --build-dir <构建目录> --source-commit <被构建提交>`，再用 `--verify` 核对。脚本会拒绝带未提交修改的构建，也会检查构建版本与 `version.txt` 一致。Release 附件由 GitHub Actions 另行构建，字节会和这里不同。

## 发布流程

合并到上游 main 后，GitHub Actions 运行全部检查；全部通过才自动创建标签 `v0.6.2` 并发布 Release，正文取自 `docs/releases/v0.6.2.md`。发布前会核对标签、`version.txt` 与编译版本一致，且该版本尚未发布。

## 验收边界

本地验证不替代 GitHub Actions（Ubuntu、Node 22）的实际结果。没有在真机上验收：SSH 失败阶段的判断、新的指纹警告弹窗和各提示的实际手感；也没有把最终发布构建刷入设备。
