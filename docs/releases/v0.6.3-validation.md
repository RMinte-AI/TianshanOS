## Codexbot 意见核验与修正

两项 P2 均成立。后台启动先等待再读取进程信息，会丢失短进程身份；改为进程自身先登记 PID／启动时刻和回传启动凭据，再执行用户命令。已登记且确认结束的运行正常清除持久记录，未确认的结果仍保持未知。真实 Linux 测试覆盖 `true` 快速退出、启动回执丢失后控制器重启核验、再次启动，以及活进程组停止；同时将探测中 dash 不支持的 `kill --` 参数改为兼容写法。所有 PID 已验证为大于 1 的数字，不放宽目标身份检查。

规则原先在模板解析前检查服务，模板引用因而绕过检查。改为固定全部动作后、执行任何动作前统一检查服务准入，直接引用和模板引用走同一路径。用例覆盖前置日志动作＋服务模板、手动／自动触发、无副作用、触发计数和冷却保持不变，以及准入允许后正常执行。未增加模板专用锁、远端删除保护或恢复重试。

真实进程仅在本地隔离 Linux 容器运行，不连接设备或业务主机；进程回收器只用于模拟远端 init，保证测试中被终止的进程组不会留下容器僵尸进程。

最终验证：完整 Ubuntu 26.04 ARM64 检查链 13 步通过，含新增真实 Linux 启动器／探测回归；macOS 原生配置测试和 ESP32-S3 固件构建通过。GitHub x86-64 检查以本次推送后的结果为准。
