# TianShanOS v0.5.2

本版本集中修复证书与 HTTPS 启动、自动化规则保存、SSH 后台任务与日志监控、WebSocket 展示采集与发送生命周期，以及 Web 管理界面的提示与操作结果判断。目标平台为 ESP32-S3，构建使用 ESP-IDF v5.5.2。

## 证书、时间与 HTTPS

- 修复网页安装设备证书和 CA 证书时 PEM 长度不正确的问题，保留解析、公私钥匹配和容量检查；分别说明缺少私钥、密钥不匹配、解析错误及存储失败。
- 证书有效期统一使用 UTC 计算，区分待校时、尚未生效、有效与过期。证书材料安装、证书有效期和 HTTPS 实际运行状态分别展示，避免仅凭材料存在就显示服务可用。
- 浏览器校时与 NTP 校时统一通知 HTTPS 启动协调逻辑。先安装后校时、先校时后安装均重新检查条件；重试有上限，用户主动停止后旧事件不会重新启动服务。
- 使用一致性证书快照和材料版本，避免并发安装与读取交叉。运行中更换材料后明确提示待应用，活动连接使用的证书不与新存储材料混为一谈；本版不增加无中断证书热替换。
- 修复通用服务管理器吞掉停止错误的问题。停止失败不会继续按“停止成功”执行重启。

## 自动化规则与配置保存

- 将规则编辑从“删除再添加”改为带版本核对的更新。冲突时保留用户草稿，不允许旧页面静默覆盖新配置；丢失写入响应时不自动重放保存。
- 保留手动触发、允许手动触发、规则启用和仪表盘展示之间的区别。切换手动模式不会清空自动条件，保存配置本身不会启动任务。
- 完善规则、条件、动作与重复执行参数的序列化，保留显式 false、缺失模板引用等信息。修复合法点号开头规则在重新加载后消失的问题。
- 为 SD/NVS 保存增加阶段标记、读回校验及恢复处理。提交结果无法确认时停止自动准入；备份同步失败不再伪装成全部成功，也不回退到陈旧配置。
- 修复旧执行与新配置并存时的所有权、取消、删除及登记回收问题。停止采用协作退出，尚未完成时明确返回等待或失败，不强制删除仍持有资源的执行任务。

## SSH 服务、日志与资源释放

- SSH 认证前统一验证主机密钥。未知或变化的主机指纹需要明确确认，不能直接使用旧的模糊信任标记继续认证。
- 查询、启动、停止和监控使用实例身份与运行代次。旧请求、旧取消和迟到的就绪消息不能影响新实例；取消观察不等于停止远端服务。
- 普通页面状态轮询读取缓存，避免持续重新建立 SSH 连接；明确核实时才查询远端。断网后的就绪恢复必须属于同一个已确认实例。
- 对连接、认证、执行、输出及关闭设置总时间预算，完善取消和错误路径的资源释放。同步 DNS 调用仍受底层解析行为限制，不承诺瞬时取消。
- 受管服务停止前核对进程身份，停止其对应进程组；去除基于相邻 PID 的猜测。启动或停止结果不明时显示未知，不自动重复执行命令。
- 原始日志完整输出，缓存使用有界预览并标明截断；改善 UTF-8、ANSI 和并发日志处理，减少认证噪声及内部敏感诊断输出。显式用户日志内容仍按原功能记录。

## Web 管理界面与操作结果

- 补齐中英文提示和参数，减少翻译键、内部枚举、变量与工程错误直接出现在主要提示中。真实文件名、路径、命令及远端原始输出保留原文。
- 按具体接口契约判断成功。HTTP 错误保留原因；退出登录区分本地凭据清除与服务端响应确认，迟到退出结果不影响新登录。
- 上传、下载、删除和配置应用区分成功、部分失败、验证失败及结果未知；下载提示只说明已向浏览器发起请求，不声称文件已经落盘。
- 修复首次页面重复初始化、重复订阅及离开页面后的迟到更新。初始化失败可重试，旧页面只清理自己的订阅和资源。
- 上传固定目的目录，验证结果绑定文件与上传代次；旧验证不能恢复应用按钮。同一路径重叠写入、无法确定最终内容时，要求重新上传验证，不自动重放上传。
- 配置应用按当前有效尝试更新提示，旧成功、旧错误和旧 finally 不覆盖新结果、不关闭新弹窗。弹窗关闭后仍保留带路径和尝试编号的任务记录。
- 上传结果与文件列表刷新结果分开呈现；旧目录响应不能覆盖当前目录。修复 Toast 定时器和重试成功被旧错误遮住的问题，动态结果以安全文本输出。
- 完善 SSH 终态、终端恢复确认与资源加载失败重试，以及 LPMU 可达性、检测未知状态的提示。不修改硬件保护策略，也不以自动电源脉冲掩盖未知结果。

## WebSocket 采集、发送与停止

- 仪表盘及其他状态主题按有效订阅和到期时间采集。最后一个订阅者离开后停止启动新的展示采集；未到发送周期时不先读取和组包，同一批次共享所需指标。底层供电保护、风扇控制和必要传感器采样频率不变。
- 修复每个主题订阅触发一次全体广播的问题。主题消息只序列化一次，再发往对应连接；连接身份与订阅代次在发送前复核，断线、文件描述符复用和重新订阅不会让旧消息发送给替代会话。原全局告警仍保留广播语义。
- 采集前联合预留消息槽、发送描述符和字节预算。容量不足时保留待服务资格，不反复执行注定无法发送的采集；跨轮次轮转主题，避免持续负载下部分主题长期得不到更新。有限消息池和发送队列不会无限增长。
- 停止分为拒绝新业务、暂停遥测、等待生产者收尾和排空已接受结果。活跃任务、停止超时或失败会逐层返回，保留发送 worker、资源和登记表，允许之后重试；没有新业务消息时，已接受结果仍继续推进。事件注销等待在途回调退出，不再把注销返回视为回调已全部结束。
- SSH Shell 只有当前会话和轮询任务就绪后才报告 connected。任务创建失败、启动中关闭及迟到状态不会覆盖终态；接受 Shell/exec 任务前预留关键结果容量，容量不足明确拒绝。SDK 入队失败保留关键结果并退避重试，不重新执行远端命令；连接断开和实际发送失败仍可能导致结果无法送达。
- SSH 普通输出在本地接受后，后续入队、发送和目标失效也反馈给所属会话；终态等待前序输出结算。已知输出不完整时明确报错，不再显示正常结束，也不向已成功的接收者重复广播。exec 网页观察结束不代表远端命令已取消或确定执行失败，后台仍遵循原业务规则。
- 全局电压保护通知使用独立配额：四条状态转换和一条周期/调试通知，各 1 KiB，消息对象、目标描述符和字节预算均与普通日志隔离。已接受转换保持顺序，不用新状态覆盖旧转换；超载明确记录失败，通知回调不等待网络。关键通知只有在 SDK 明确拒绝入队时重试，最多 300 次、每次间隔至少 100 ms；实际 socket 失败不重发不确定帧。
- 角色切换同步日志资格，排队日志绑定原订阅代次。日志切到终端/SSH、取消后重新订阅，均不会恢复旧日志的发送资格。
- 总消息缓冲仍限制为 1 MiB，其中保护通知独占 5 KiB 常驻缓冲，其他消息共享剩余预算；exec 任务接受前预留最多 512 KiB，Shell 预留 4 KiB。预留会占用堆和可用发送容量，资源不足或上一结果尚未排空时，新任务可能被暂时拒绝。本版未新增 `/ws` 独立认证或主题授权，定向发送不等同于补齐该安全边界。

## 升级与兼容性说明

- 升级前请备份规则、SSH 主机/命令及相关配置。本版本没有新增分区，也不会主动清空 NVS 或替用户重新签发证书。
- 同名加密配置包、旧单文件规则和部分镜像来源保持只读保护；并非所有历史配置格式都支持直接网页修改。
- 旧固件仅留下单 PID、无法核实身份的活跃进程不会被新版本猜测性终止。需要操作人员先确认旧实例退出，再交由新版本接管。
- 新后端的规则写入要求版本信息；使用旧缓存页面可能不能完成写入，升级后应刷新管理页面。固件与 WebUI 镜像应配套升级。
- ready 表示已取得对应实例的日志就绪证据，不代表推理服务持续健康，也不是性能测试结论。

## 验证边界

已补充生产函数回归、模拟存储故障与并发测试，以及实际网页入口的中英文浏览器测试；构建与发布由本次提交对应的 GitHub Actions 执行。测试详情保存在仓库的证书、运行时、提示语修复记录及 [WebSocket 修复记录](https://github.com/RMinte-AI/TianshanOS/blob/main/docs/repair/ws-subscriptions/reviewer-fixes/README.md)，以及 [F1/F2 后续修复记录](https://github.com/RMinte-AI/TianshanOS/blob/main/docs/repair/ws-f1-f2/README.md) 中。

本版本未将模拟测试等同于真实设备验收。实际 TLS 握手和证书切换、真实 SSH/SFTP/SCP、板卡断电恢复、旧配置升级、三模型联动、长期堆内存与时延，以及 WebSocket 的双核调度、慢连接/RST/LRU、反复启停和 worker 栈水位仍需部署环境验证。请先在可控设备上验收，再安排生产升级。

## 固件附件

Release 附带应用固件 `TianShanOS.bin`、WebUI 文件系统 `www.bin`、bootloader、分区表、OTA 初始数据及刷写参数（以该次构建实际附件为准）。本 Release 发布流程不连接设备，不自动刷机或重启。
