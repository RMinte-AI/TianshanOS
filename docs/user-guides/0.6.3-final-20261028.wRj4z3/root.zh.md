## 10. 终端与系统日志

“终端”只对 root 显示。它可以直接执行设备控制台命令，也可以查看设备日志。命令可能立即改变设备状态，输入前应确认命令来源、参数和影响。

### 连接并使用终端

1. 点击顶部导航中的“终端”。
2. 等待页面显示“已连接到设备”和 `tianshan>` 提示符。
3. 输入 `help`，查看当前固件提供的命令。
4. 输入命令并按 Enter。等待输出结束并重新出现提示符。

页面显示“未连接到设备”时，输入不会执行。连接断开后页面会提示重新连接；恢复连接后再提交命令，避免重复执行。

终端提供以下键盘操作：

| 操作 | 作用 |
| --- | --- |
| Ctrl+C | 清除当前输入，并请求中断命令；能否停止取决于命令是否支持中断。 |
| Ctrl+L | 清屏。 |
| ↑ / ↓ | 查看本次页面会话中的命令历史。 |
| ← / → | 在当前输入中移动光标。 |

页面顶部的“清屏”只清除当前显示，不会撤销已经执行的命令。“断开”会结束当前终端连接。

### 进入远程 SSH Shell

SSH Shell 会把后续键盘输入发送到远程主机。连接前应确认目标地址、用户和认证方式，并完成安全指南中的 SSH 准备工作。

1. 输入 `ssh --help`，查看 SSH 命令说明。
2. 按以下格式填写实际主机地址和用户名：`ssh --host <主机地址> --user <用户名> --shell`。尖括号及其中的文字都需要替换。需要指定端口时，在 --shell 前添加 `--port <端口>`。
3. 等待终端显示远程连接成功，再输入远程命令。
4. 按 Ctrl+\ 退出 SSH Shell，返回 tianshan> 提示符。

不要在屏幕共享、录屏或可被他人查看的终端中输入明文凭据。

### 查看系统日志

点击终端页顶部的“系统日志”打开日志窗口。

- “级别”控制最低显示级别。选择 ERROR、WARN+、INFO+ 或 DEBUG+ 可以缩小日志范围。
- “TAG”按日志来源筛选。
- “搜索”按关键词筛选当前日志。
- “自动滚动”开启时，页面会跟随最新日志。
- 刷新按钮会重新读取历史日志。
- 清除按钮只清除当前窗口中的日志显示。

筛选后没有内容时，可以先清空 TAG 和关键词，再调整级别。关闭日志窗口不会停止设备服务。

## 11. 管理和运行远程指令

“指令”保存可重复使用的 SSH 命令，并在选定的主机上运行。“远程主机”指 SSH 连接的 AGX、LPMU 等设备。主机和密钥在“安全”页面管理，准备方法见安全指南。

### 连接前核对主机指纹

指纹用于核对主机身份。以下步骤适用于网页“安全”中的 SSH 主机测试，不是终端 SSH Shell 的确认流程。

1. 提示指纹未登记或发生变化时，先停止重复执行指令。
2. 进入“安全”，找到目标 SSH 主机，点击“测试”。
3. 首次连接时，通过可信渠道向主机管理员核对地址和指纹。一致后才点击“信任并连接”。
4. 指纹变化时，窗口显示已保存和当前指纹，默认选中“取消”。先核对变化原因；不能确认就取消。确认新指纹可信后，才点击“更新主机密钥”。

重装系统可能改变指纹，也可能是连到了其他主机或有人冒充主机。不要删除旧指纹来跳过核对。

### 选择主机并查看指令

1. 点击顶部导航中的“指令”。
2. 在“选择主机”中选择目标主机。
3. 在“命令列表”中查看该主机的指令。

“孤儿命令”使用的主机已不存在，不能执行。先检查它是否仍被使用，再决定删除或在有效主机下重新创建。当前导入窗口没有重新绑定主机的选项。

### 新建或编辑指令

创建前，先在目标主机上确认命令和权限。删除数据、断电、重启和覆盖文件等操作，不应配置成容易误触的任务。

1. 选择主机后点击“新建指令”。编辑时，点击现有指令的编辑按钮。
2. 填写唯一的“指令 ID”。只使用字母、数字、下划线和连字符，不以下划线或连字符开头或结尾。
3. 填写“名称”和“命令”。多行命令每行一条。
4. 按需填写描述，选择图标或 SD 卡中的图像。
5. 检查运行方式和结果匹配设置，再点击“保存”。

名称帮助用户辨认任务，ID 用于让自动化找到它。现有指令的 ID 不能修改。需要新 ID 时，新建指令，并调整使用它的模板和数据源。

提示“配置已经改变”时，窗口内输入不等于已保存。先复制需要保留的内容，再关闭并重新打开编辑器，核对新配置后保存。不要连续提交，也不要把关闭窗口当作保存草稿。

### 执行并查看结果

1. 点击指令卡片上的执行按钮。
2. 在“执行结果”中观察输出和状态。
3. 页面提供“取消”时，可请求中断当前执行会话。继续检查状态和输出，确认是否已停止。
4. 点击“清除”只移除结果显示。

“取消”和“清除”都不会撤销已经完成的远程操作。结果中的成功、失败、提取内容和最终状态，还取决于下面的匹配设置。

### 配置结果匹配

- “期望匹配”：输出包含指定文本时标记成功。
- “失败匹配”：输出包含指定文本时标记失败。
- “提取正则”：用一个 `(.*)` 捕获组保存目标内容。
- “命中即停止”：匹配成功后终止仍在持续运行的命令。
- “超时 (秒)”：等待匹配结果的时间。仅在配置成功或失败匹配，或启用“命中即停止”时生效。
- “变量名”：保存状态和提取结果，供自动化选择。

选择稳定、明确的匹配文本。过于宽泛的文字可能误判。保存后先执行一次，检查“匹配结果”，再让规则使用这些变量。

### 使用后台执行和服务模式

“后台运行 (nohup)”让命令在远程主机上继续运行，关闭 WebUI 或 SSH 断开不会停止它。后台运行需要 SSH 密钥认证；先按安全指南部署公钥，并使用关联的主机配置。

“服务模式”用于观察后台任务是否进入可用状态。启用后，填写“就绪匹配”和“变量名”，再按需调整：

- “就绪匹配”：日志出现这些文字时标记为就绪，可用 `|` 分隔多个模式。
- “失败匹配”：日志出现这些文字时标记为失败。
- “就绪超时 (秒)”：最长等待时间。
- “检测间隔 (毫秒)”：检查日志的间隔，1000 毫秒等于 1 秒。
- “变量名”：保存 checking、ready、timeout 等状态。

启动、核验和停止都可能需要等待。请求被接受不代表已经完成；状态无法确认时，先检查连接，不要立即再次启动。

### 在“后台运行”中管理任务

“指令”和“自动化”页面都有“后台运行”入口；root 也可从系统页进入。原指令即使已删除，仍可在这里处理保留的运行记录。

1. 点击“后台运行”，核对任务名称、主机地址和账号，找到要处理的那一次运行。
2. 显示“待检查”或“无法确认远端状态”时，点击“核验远端状态”，等待结果。设备重启后需要重新核验；列表刷新只更新记录，不替你连接远端检查。
3. 点击“查看日志”，读取原主机日志最近 100 行。点击“实时查看”持续刷新；“停止查看”只停止刷新，不停止任务。
4. 需要结束任务时，点击“停止”并确认。等待确认已停止，再决定是否重新启动。

日志或状态检查失败，不等于日志没有内容，也不代表进程已经退出。按原因检查主机连接，再核验；不要因为检查失败而重新启动任务。

删除指令、切换配置或重启 TianshanOS，不会结束远程主机上的后台进程。运行记录保留原主机信息；重建同名指令或修改主机后，旧任务也不会转移到新主机。处理旧任务时，检查这里显示的原地址。

自动规则可能在任务停止后再次启动它。需要持续停止时，先检查并按需停用对应规则，再停止任务。

### 导入和导出指令

- 用指令的导出按钮保存配置包，可按页面选项包含关联主机。
- 点击“导入指令”，选择 `.tscfg` 文件，核对指令及包内可能包含的主机信息。只有确定替换同 ID 配置时，才勾选覆盖。
- 按安全指南检查来源、证书和签名。预览后文件、凭证或配置改变时，点击“重新检查配置包”，重新核对后再导入。

导入成功后保存到当前使用的配置，无需为这次导入重启；已有的自动化暂停设置不变。先核对主机和任务影响，再执行。需要更新内部副本时，按第 13 章操作。

### 删除指令

点击删除按钮，先看受影响的模板和规则。按第 12 章选择替换关联，或解除关联并停用相关规则，再确认删除。

删除不要求先确认远端服务已停止，也不会替你停止它。仍需结束任务时，到“后台运行”找到原任务并停止。删除本地主机配置也不等于撤销远端公钥，撤销方法见安全指南。

## 12. 自动化管理

“自动化”把数据和操作连接成可重复执行的任务。先建立数据源和动作模板，再用规则决定何时执行。

```text
自动执行：数据源 → 变量 → 规则判断 → 执行动作
手动执行：系统页快捷操作 → 执行动作
```

数据源读取数据，变量保存值，规则判断条件，动作模板定义任务。“显示在面板”和“允许手动触发”分别设置。自动规则也能显示在面板中。

### 查看和控制自动化引擎

页面顶部显示引擎状态、规则数、变量数、数据源数、触发次数和运行时长。

| 操作 | 影响 |
| --- | --- |
| “启动” | 启动已停止的引擎，处理允许执行的规则。 |
| “暂停” | 暂停后续自动判断，已有动作可能继续。需要恢复时先停止，再启动。 |
| “停止” | 尝试停止规则判断、数据读取和后续动作安排，保留配置。等待确认；超时不表示已停止。 |
| “重载” | 重新读取当前使用位置的已保存配置。先保存编辑内容，再核对结果；不是恢复另一份副本。 |

“配置与备份”中的“启用自动化”和“停用自动化”用于明确保存这套配置的启停选择。不要把引擎一次暂停或停止，当成已经停用全部规则或结束远程服务。方法见第 13 章。

操作前检查散热、告警和其他持续任务是否受影响。远程后台任务需要在“后台运行”中停止并确认。

### 完成一条最小自动化流程

1. 创建数据源，用测试功能检查连接和要读取的字段。
2. 启用数据源，点击“查看变量”，检查数值和更新时间。
3. 创建动作模板，检查参数后点击“测试”。测试会发出真实执行请求，先确认设备和远程主机允许本次操作。
4. 创建规则，先关闭“立即启用”，设置条件、冷却时间、动作顺序、延迟和重复方式。
5. 按需设置“显示在面板”和“允许手动触发”。
6. 保存后再启用，观察变量、触发次数及实际结果。

### 管理数据源

在“数据源”点击“添加”，选择类型：

| 类型 | 用途 |
| --- | --- |
| “REST API” | 定期读取一个 HTTP 地址返回的数据。 |
| “WebSocket” | 接收持续连接推送的数据。 |
| “Socket.IO” | 接收 Socket.IO 服务的事件数据。 |
| “指令变量” | 读取已配置远程指令的结果。 |

1. 填写唯一 ID、显示标签和该类型要求的连接信息。
2. 用测试功能检查连接，地址、认证和字段以数据提供方的信息为准。
3. 对前三种类型，从测试结果选择要读取的字段。Socket.IO 事件名称留空时，可尝试发现事件。
4. 对“指令变量”，选择主机及已配置变量名的指令，设置检测间隔。
5. 保存、启用，再用该行的“查看变量”检查结果。

数据源行提供启用开关、变量查看、导出和删除。停用或删除前检查哪些规则还在使用它，避免影响任务。导入前核对类型、ID 和覆盖内容，并按安全指南检查来源与信任要求。

### 查看变量

点击数据源行的眼睛图标“查看变量”，查看名称、类型、值和更新时间。远程指令也有变量入口。

- 核对名称和数据源，确认值与类型适合规则比较。
- 用更新时间判断数据是否仍在更新。
- 没有数据时，检查数据源是否启用，再测试连接和字段；远程指令变量还要检查指令执行结果。

### 创建和测试动作模板

在“动作模板”点击“添加”，选择任务类型：

| 类型 | 作用 |
| --- | --- |
| “CLI 命令” | 执行设备本地控制台命令。 |
| “SSH 命令” | 执行“指令”页已保存的远程指令。 |
| “LED 控制” | 控制 LED 颜色、动画或矩阵内容。 |
| “日志记录” | 按指定级别写入日志。 |
| “设置变量” | 为自动化变量赋值。 |
| “Webhook” | 向指定地址发送 HTTP 请求。 |

填写唯一 ID、名称和该类型的参数，可设置延迟与“异步执行”。异步动作在后台继续；提交后通过日志、变量或目标设备确认最终结果。

- CLI：填写命令，可按需设置结果变量和超时。
- SSH：选择主机和指令，核对预览。
- LED：选择设备及支持的颜色、动画、亮度、文字、图像、QR 码或滤镜。
- 日志：选择级别，填写消息，可引用变量。
- 设置变量：填写变量名和值。
- Webhook：填写提供方给出的 URL，选择 GET、POST 或 PUT；需要时填写请求内容。测试会向目标地址发出请求，先确认对方允许。

当前本地 Webhook 动作可以执行，但签名规则包仍不支持包含 Webhook。这项限制只针对配置包导入。

点击“测试”可能执行断电、重启、远程命令或外部请求。显示“已排队”只表示等待执行，不代表完成；到“终端”的“系统日志”或目标设备检查结果。

图片或字体无法读取时，先核对原 SD 卡和路径，或重新选择可用资源。应急副本只保存任务配置，不包含这些文件。

### 创建规则

1. 在“规则列表”点击“添加”，填写唯一 ID、名称和图标。
2. 选择“条件逻辑”：AND 要求所有条件满足；OR 要求任一条件满足。
3. 设置“冷却时间”，限制自动触发频率。单位为 ms，1000 ms 等于 1 秒。
4. 添加条件，选择变量、比较方式和值。支持等于、不等于、大于、大于等于、小于、小于等于、值变化和包含；值的类型须与变量相符。
5. 添加动作模板，设置顺序、延迟、重复和动作条件。
6. 决定是否开启“显示在面板”和“允许手动触发”。
7. 保存后核对内容，再启用。首次配置可先关闭“立即启用”。

最多保存 64 条规则，不表示能同时执行 64 个任务。命令长度和条件、动作数量也会影响可保存的配置大小。

数字必须是有效的具体数值。比较值只填写单个值，不填写一组数据；内容须符合所选类型。页面报错时先修正，再保存。

保存成功后当前配置会更新，不需要为切换规则而重启。提示内部副本“尚未包含最新修改”时，不代表本次保存失败；确认修改正确后，再按第 13 章保存应急副本。

### 配置动作重复和执行条件

| 方式 | 含义 |
| --- | --- |
| “单次” | 每次触发执行一次。 |
| “条件持续时重复” | 按单个动作的条件重复，每轮最多 100 次。 |
| “指定次数” | 按设置次数和间隔重复；每次执行前仍检查动作条件。 |

动作条件与规则触发条件分开设置。“条件持续时重复”未设置动作条件时，会重复到每轮上限；规则以后仍可能再次触发。

停用规则会阻止新的触发，已发出的操作或远程任务仍需检查。停止、删除和更改配置都不会撤销已完成的操作。

### 创建快捷操作

“仅手动触发”“显示在面板”“允许手动触发”分别决定是否只手动运行、是否显示卡片、是否允许执行。

1. 填写 ID、名称和图标，开启“仅手动触发”。这种规则不需要自动触发条件。
2. 添加动作模板，检查延迟、重复和动作条件。
3. 开启“显示在面板”和“允许手动触发”，保存并启用规则。
4. 回到系统页，核对卡片名称、状态和实际结果。

自动规则显示在面板后，仍可能按条件自动运行。停用规则的卡片可能还在，但不能启动。为 admin 提供的卡片应使用能说明实际任务的名称。

### 导入规则配置包

从“规则列表”的导入入口选择 `.tscfg` 文件，不要用文件上传或安全页“仅验证”代替。确认前检查：

- 当前保存位置可写。使用 SD 卡时检查卡；使用内部应急配置时检查内部存储。
- 设备证书、匹配私钥和 CA 链可用，设备时间已确认。
- 部署管理员已指定可信的配置签发方。root 登录或安装 HTTPS 证书不代替此项设置。
- 需要的模板、指令和主机齐全。规则导入不会自动补齐它们；规则已启用时，还要检查相关配置是否已启用。

1. 选择文件，等待“来源、目标设备和规则内容已验证。”。
2. 核对名称、ID 和“规则摘要”，展开“查看规则内容”，检查条件、动作、目标和启用状态。
3. 已有同 ID 配置时，核对预览中的内容和启用状态，确认要替换才勾选“覆盖已存在的配置”。
4. 预览后文件、凭证或配置变化时，点击“重新检查配置包”，重新核对。
5. 确认导入并等待保存结果，随后检查规则和实际任务结果。

导入成功后保存到当前配置并生效，不需要重启。已有暂停不会自动解除；如果允许执行，已启用的自动规则可能按条件运行。因此应在确认导入之前检查任务影响，不是等重启前才检查。

导入的规则可以在设备上编辑、启停或删除。本地修改不等于原签发方认可过修改内容。新包每次导入仍需验签，不能用旧验证结果跳过。

设备证书能用于 HTTPS，不代表有权签发配置包。签发权限不足时，请提供方提供合规包，不要关闭验签。当前含 Webhook 的签名规则包仍不能导入。

### 删除规则、模板、指令或主机

删除前无需先停止远端服务，但删除配置也不会停止它。先核对哪些规则、模板和任务会受影响，再决定是否删除。

1. 点击目标的删除按钮，核对名称和关联清单。
2. 普通“删除”中，按页面提供的选项选择替换关联，或“解除关联并停用相关规则”。
3. 阅读将被停用或改变的项目，再确认删除。
4. 刷新列表核对结果。需要结束原后台任务时，另到“后台运行”停止并确认。

删除规则会从当前配置移除，不再等待重启。删除模板会解除相关动作并停用受影响规则。删除指令后，相关模板会保留为停用草稿并清空命令关联；相关规则也会解除关联并停用。删除主机还可能影响命令和数据源，以确认清单和实际列表为准。

需要替换关联时，先确认替代项的实际目标和作用，不能只因名称相似就选它。删除后检查受影响配置，修正并确认允许执行后，再启用相关规则。

有卡时删除只改变当前 SD 配置，不会更新内部旧副本。确认删除结果后，如不希望应急时恢复旧任务，再保存应急副本。

### 使用“最终强制删除”

确需删除，而普通关联处理无法完成时，可在删除窗口选择“最终强制删除”。它会删除目标，清理能确认的关联，并停用受影响规则，不会停止远端任务。

无法确认完整影响范围时，页面要求勾选“我确认暂停自动化，并继续删除。”。确认可以暂停自动化后，再操作。完成后自动化保持暂停；检查剩余配置，确认可以运行，再到“配置与备份”点击“启用自动化”。

强删不跳过管理权限、配置变化检查或存储写入错误。页面卡片消失不等于永久删除成功；查看结果并重新读取列表。不要删除 SD 文件来绕过保护。

提示配置已经改变时，点击“重新检查删除影响”，重新阅读清单、重新选择处理方式，再确认。这个按钮只重新检查，不自动删除。

### 保存或导入未完成时

| 页面情况 | 下一步 |
| --- | --- |
| 配置已经改变 | 先保留未保存内容。重新打开编辑器，或重新检查导入、删除影响，再确认。 |
| 保存结果未确认 | 先重新读取列表和配置位置；仍无法确认时查看系统日志，不重复提交。 |
| 存储不可写或空间不足 | 检查当前使用的卡或内部存储，处理后重新检查。写入失败时，不要假定改动已保存。 |
| 缺少模板、指令或主机 | 补齐提示指出的配置，核对启用状态，再重新验证。 |
| 签发方不可信、用途不符或不是本设备的包 | 请部署管理员或提供方核对；不要改包内名称或关闭验证。 |
| 时间尚未确认 | 在系统页“网络与时间”同步并核对，再重新验证。 |

## 13. 配置与备份

先确认设备正在使用哪套配置，再决定保存、恢复或切换。“配置与备份”位于“自动化”页；这些操作应由 root 用户完成。

### 看懂当前配置位置

1. 进入“自动化”，点击“配置与备份”。
2. 查看“当前使用”：是“SD 卡配置”，还是“内部应急配置”。
3. 查看 SD 卡是否可用、内部保存时间和“副本状态”。

| 当前情况 | 含义 |
| --- | --- |
| 正在使用 SD 卡配置 | 日常新增、修改和删除保存到 SD 卡，内部副本不会自动跟随更新。 |
| 正在使用内部应急配置 | 新增、修改和删除直接保存在设备内部，不再另存一份应急副本。 |
| 尚未包含最新修改 | 内部副本与当前配置不同，不一定是保存故障。确认任务配置正确后，手动更新副本。 |

副本一起保存规则、动作模板、SSH 命令、关联主机、数据源和需要保存的用户变量定义。它不包含私钥、图片、字体、日志或远端运行状态，不是整机备份。

网络、风扇、温度和灯光等系统设置独立保存在设备内部。恢复自动化副本不会把它们或密钥一起恢复成旧值；插入旧卡也不会自动恢复系统设置。

### 保存应急副本

当前使用 SD 卡配置时：

1. 先检查规则、主机和实际任务，确认要保留的是当前这套配置。
2. 点击“保存应急副本”，等待“整套应急副本已保存。”。
3. 核对内部保存时间和副本状态。

保存会替换以前的内部副本，不是保留多个历史版本。之后继续修改 SD 卡时，内部副本保持原样；需要时再保存。保存副本不停止远端任务，也不备份它们的当前运行状态。

### 从应急副本恢复

当前使用 SD 卡配置且内部有有效副本时：

1. 先看保存时间，确认副本没有过旧或不该恢复的任务。
2. 点击“从应急副本恢复”，阅读新增、修改、移除及启停变化。
3. 确认可以用副本替换当前整套 SD 配置，再确认。
4. 等待完成，核对规则、模板、指令、主机和当前启停状态，无需为恢复重启设备。

恢复是整套替换，不是合并。旧副本可能带回后来删除的规则，或移除后来新增的任务。没有可用副本时不能恢复；读取失败也不能当作空配置覆盖。

确认窗口会说明哪些自动规则可能运行，以及是否保持暂停。按原条件运行的自动规则不需要再次手动点击；手动规则仍需点击。先确认任务可以运行，再解除暂停。

### 无卡时继续使用和编辑

SD 卡缺失或无法读取时，有可用内部配置就会进入应急模式。原来已启用的自动规则按条件运行；已有暂停仍保留。没有可用配置时，按页面原因处理，不要假定任务已恢复。

应急模式下，可以新增、修改和删除，保存直接写入内部。图片、字体和日志仍可能依赖 SD 卡。配置恢复成功不等于这些资源也可用。

### 重新插卡后作出选择

1. 插入可用 SD 卡，在“配置与备份”点击“检查 SD 卡”。
2. 确认当前仍使用内部配置，阅读两个选择。
3. 需要使用卡内原任务时，选择“使用 SD 卡配置”；内部配置保留。
4. 需要把无卡期间的修改带回卡上时，选择“将当前配置保存到 SD 卡并使用”，阅读差异并确认覆盖。

插卡不会自动切换、覆盖或合并。也可以关闭窗口，继续使用内部配置；在作出选择前重启，不会代替你选择。

“将当前配置保存到 SD 卡并使用”会替换卡内整套配置。成功后核对当前来源；若提示已保存到卡但尚未切换，当前仍使用内部配置，先读取状态，再选择“使用 SD 卡配置”，不要直接重复覆盖。

### 启用或停用自动化

在“配置与备份”使用“停用自动化”或“启用自动化”，可以明确保存当前配置的启停选择。强删要求暂停后，必须先检查配置，再手动启用；导入或来源切换不会自动解除已有暂停。

恢复或切换可能带来不同的规则和启用状态。确认前阅读预览，确认后再看状态。任何配置操作都不替你停止远端后台服务；需要结束的任务仍到“后台运行”单独处理。
