## 契约与使用边界

- 旧客户端缺少 expected_revision 时不能静默覆盖。冲突保留草稿；网络中断后只读回核实，不自动重放保存。显式 false 与字段缺省有区别；模板解析失败保留引用，不能凭猜测把后台规则变成卡片。
- 规则读者 acquire/release；入队动作持有模板、主机和 SSH 命令的执行快照。运行中改身份/删除被拒绝，改展示或模式不撤销已受理执行。确认停止后允许重新绑定。
- 普通 SD JSON 使用 pending/previous 文件、NVS 阶段标记、读回校验和恢复；NVS-only 使用双 bank 和最终选择标记。权威提交不确定时停止自动准入。镜像失败明确返回已应用但备份未同步，不回退到陈旧 NVS。
- 同名加密 `.tscfg`、旧单文件 `rules.json` 和缺 SD 时的镜像来源维持只读，修改前报错；不解密降级、不删除旧配置。不是所有历史格式都可以直接网页编辑。
- 服务记录最多 64 项（既有 SSH 命令上限），以命令 ID、配置目标 host/port、受管路径保护实例；远端启动前查询，并用原子 mkdir 锁目录避免失联后重复启动。主机别名不会自动合并为物理机器身份；远端同一路径锁仍约束同名实例。
- 新受管进程用独立 session/process group，记录准确 PID 和 `/proc` 启动时间；停止只在核对身份后 TERM 该组，确认后才 stopped。删除了 PID-1 猜测。**旧固件只有单 PID、无法证明身份的活跃进程可以显示运行，但拒绝自动误杀；需操作人员确认旧实例退出，再由新版本接管。** 这是安全兼容边界，未擅自迁移现场进程。
- 停 watcher 仅取消观察；迟到 READY 受服务 generation 阻挡。ready 是历史日志证据，不代表持续 HTTP 推理健康。启动 exec 后断线、监控创建失败或停止结果未知都显示 unknown。
- 无新常驻任务。watcher 仍为 8KiB 栈、core 1、priority 5；默认查询/日志轮询频率未提高；页面隐藏、重复请求、已移除弹窗的迟到响应受控。
- 普通 SSH exec 默认每个输出流最多 64KiB，watcher 为 128B；溢出返回错误。大文件应走原文件传输接口。交互 shell、SFTP/SCP 仍需真实服务端回归，不以编译代替运行验证。
- **DNS 是例外边界**：lwIP `gethostbyname()` 同步调用仍受原生解析重试约束，无法在其内部做到 100ms 取消。返回后立即检查总 deadline。已核对 SDK 默认 DNS_MAX_RETRIES=4、DNS tick=1s；多服务器/重试的实际耗时未测，不承诺 DNS 也在一个轮询间隔内退出。
- 显式“日志动作”仍会记录用户要求的文本；本轮移除的是内部诊断泄露，不提供任意用户日志内容的全局秘密识别器。

## 静态资源核算（目标工具链，非板卡测量）

从最终 ELF DWARF 读取 sizeof；旧类型由 HEAD 头文件使用同一 Xtensa 编译器编译对象验证。详见 `evidence/resource-sizeof.txt`。

| 项目 | 基线 → 本轮 / 静态值 |
|---|---|
| rule 结构 | 224 → 240B，+16B/条 |
| 每条额外所有权记录 | payload 16B（PSRAM）+ meta 3B；连同结构增量共 35B/条，未含 allocator 自身开销，低于 64B 设计目标 |
| action 结构 | 984 → 992B，+8B/动作；执行专用字段不序列化 |
| 日志固定捕获工作区 | 1624B，共两个槽，低于 2048B |
| watcher 固定槽表 | 32 × 24 = 768B 内部 RAM |
| 规则上下文 | 共 160B（包含原有字段）；meta 已含其中 96B |
| 服务登记表 | 64 × 240 = 15360B，指定 PSRAM，失败不回退到内部 RAM |
| 新同步对象 | 按 7 个相关 mutex 的全部容量保守计 7 × 92 = 644B；实际部分是原有锁 |
| 动作队列 | 每项 1032B，16 项；结构增长连同对齐保守计增量不超过 256B |
| 其他控制 | guard 100B、回调任务表 32B、指针/原子/锁控制保守预留 256B |
| 新增常驻内部上界估算 | 1624+768+160+644+256+100+32+256 = **3840B**；特意把部分旧容量也计入。低于 8KiB 目标；链接器整体变化与运行堆仍不能由此推定 |
| 新增常驻任务 | 0（静态任务创建路径审查）；实机任务数未测 |

临时空间按实际上限计算，不把 PSRAM 当无限内存：令 C/A 为一条规则条件/动作数，各不超过 255。一个配置负载约 `16 + 144*C + 992*A`；一个冻结执行约 `992*A + 2368*S`，S 为需绑定的 SSH 动作数。每个同步结果 288B PSRAM 加现有二值信号量；watcher 配置 616B PSRAM，探测命令缓冲 3072B PSRAM，不增加栈。API 候选、引擎规范化候选、一个退役负载与实际执行快照可能同时存在；每次提交还有最多 `32*240=7680B` 的标量持久化视图。队列仍上限 16，退役配置全局上限 1，编辑候选门禁 1。JSON 使用工程已有 allocator，序列化的临时内存另计；分配失败明确拒绝，不无限回退内部 RAM。255 个动作的极限配置不保证在实际剩余内存下装得下。

NVS 分区维持 **48KiB**，还与证书/密钥/其他配置共享。双 bank 的最低数据量约为两份配置 JSON 加两份 bank metadata 和 guard，再加 NVS 页/条目/GC 开销，**不能承诺 32 条任意大规则都能放入 NVS**。模拟测试覆盖写失败时保留旧版或拒绝不确定恢复的语义；实际满容量、剩余空间、擦写耗时和断电未测。SD 权威保存后的镜像容量不足会显示“已保存，备份未同步”；NVS-only staging 空间不足拒绝新提交。未扩大分区。R01 保留未验收。
