# 自动化配置使用与存储

规则、动作模板和 SSH 命令共同组成一个配置集合。例如，“温度过高”规则引用“启动散热服务”模板，模板引用“AGX 散热”命令，命令再引用 AGX 主机设置。保存、备份和恢复会一起处理这些定义，以及数据源和需要保存的用户变量。

## 保存到哪里

| 内容 | 位置 | 何时更新 |
|---|---|---|
| 密钥及必要密钥元信息 | 原 48 KiB 密钥区 | 密钥管理操作 |
| 网络、风扇、温度、LED、UI、认证等系统设置 | 128 KiB 系统 NVS | 保存对应设置时 |
| 当前自动化配置 | SD 卡 `/sdcard/config/automation/state.json` | 正常模式下保存时 |
| 自动化应急副本 | 内部 2 MiB 配置区 `/autocfg/state.json` | 有卡时点击“保存应急副本”；应急模式下直接保存 |

上限为 64 条规则。条数与同时执行任务的数量不同；命令长度、条件和动作数量也会影响配置大小。

应急副本保存配置，不保存图片、字体、日志、远端服务状态或私钥。主机设置保留对密钥的引用，私钥仍由密钥区管理。缺少图片、字体或密钥时，执行结果会说明缺少的内容。

## 两个按钮

- **保存应急副本**：把当前整套配置保存到内部。之后继续修改 SD 卡配置，内部副本保持原样，直到再次点击此按钮。
- **从应急副本恢复**：先显示哪些内容会增加、替换或移除；确认后，用内部整套配置恢复当前工作位置。列表随后刷新，无需重启。

这两个操作都会处理规则、模板、命令及其配置依赖。它们不会停止或重启远端服务。

## 无卡与重新插卡

启动时卡缺失或无法读取，且内部有可用配置，设备自动进入应急模式，并运行其中已经启用的自动规则。手动规则仍需点击执行。网络、风扇等基础系统设置继续从系统 NVS 读取。

应急模式允许编辑；保存直接写入内部配置。没有可用内部配置时，界面说明原因，用户可创建配置。读取损坏文件失败不会被当成一套空配置覆盖。

重新插入 SD 卡后，继续使用当前内部配置，显示两个选择：

- **使用 SD 卡里的配置**：切换到卡内配置，内部配置保持原样。
- **将当前配置保存到 SD 卡并使用**：先显示差异，确认后用当前配置更新 SD 卡，然后切换到 SD 卡。

作出选择前重启，也会保留这次待选择状态。SD 卡中没有配置，不会自动把内部副本复制过去；需要明确选择保存到卡。

## 删除如何处理

| 对象 | 普通删除 | 强制删除 |
|---|---|---|
| 规则 | 直接移除 | 同样移除目标规则 |
| 动作模板 | 无引用直接删除；有引用可替换模板，或解除引用并停用相关规则 | 移除目标模板、解除引用并停用受影响规则 |
| SSH 命令 | 无引用直接删除；有引用可替换命令，或解除关联 | 移除命令；关联模板保留为停用草稿并清空命令引用；受影响规则解除关联并停用 |

例如删除“AGX 散热”命令后，规则会显示为停用，用户可重新选择有效动作再启用。不会保留一条看起来正常、实际找不到动作的启用规则。

删除前会列出具体受影响项。普通检查无法确认影响范围时，仍可确认“暂停自动化后强制删除”；自动化保持暂停，修正配置并明确启用后才继续。

强删不等待远端停止，也不要求服务状态必须已确认。管理权限和真实写入错误仍会如实处理：存储无法写入时，不能把网页卡片消失当作删除成功。所有删除只修改当前工作配置，另一份手动副本不会自动更新。

## 后台服务与配置分开

“远端”是 SSH 连接的 LPMU、AGX 等主机。删除本机命令定义不会结束这些主机上的进程。已启动的后台服务以独立记录保留核验和停止入口，即使命令被删除或控制器重启也能找到。

“无法确认”表示目前没有可靠结果，例如重启后尚未核验、网络连接失败或核验超时。它不会被显示为“正在运行”。核验是一次明确操作；列表刷新不偷偷重复发起 SSH 连接。

## 升级与旧数据

新分区表通过匹配的 USB／串口升级包写入；升级包同时更新两个应用槽，保留密钥和已有数据区。首次启动按各旧模块原有的读取、验签规则迁移，成功后退出旧的分列表保存和双向同步流程。

系统设置完成迁移后，旧 SD 系统文件不再自动覆盖设置。自动化完成迁移后，只有统一配置集合参与正常读写；不能通过文件管理器直接删除、覆盖其内部管理文件，请使用配置页面的正式操作。
