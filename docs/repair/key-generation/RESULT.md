# 密钥生成修复验收记录

2026 年 10 月 9 日。本文件记录密钥生成修复独立验收时的结果，当时未提交、推送或刷机。该修复随后纳入 0.6.1 统一发布，发布范围及验证边界见 [0.6.1 发布验证](../../releases/v0.6.1-validation.md)。独立修复范围以 [PLAN.md](PLAN.md) 为准。

## 修复结果

- 元数据和索引写入失败现在返回失败，不再虚报保存成功；索引按完整 ID 比较，`app` 与 `p` 可以分别保存。
- 新生成操作在运算前和写入前检查 ID 占用、实际 NVS 名称长度及现有 8 项上限。已有密钥和历史残留不会被新建覆盖或删除。旧记录读取、CLI 调用签名、导入时公钥可选、密钥类型及元数据字段保持。
- 新建失败只清理本次 ID。索引恢复失败时保留材料，返回原失败阶段和清理错误；原索引不存在时恢复为不存在，避免失败操作额外留下空索引记录。保存完成后的响应失败不会删除密钥。
- 存储写入、删除及使用时间更新共用模块内写锁；密钥计算在锁外进行，写入时重新核对。使用静态锁，避免服务停止时删除仍可能被等待者使用的锁；服务保持停止时，在途生成不会继续写入。
- 页面持续显示正在生成，禁止重复提交；确认保存后关闭所属弹窗并刷新密钥表。存储失败、结果未知、保存成功但刷新失败分别反馈。结果未知最多补查一次记录，不自动重发生成请求，查到同 ID 不冒充本次生成成功。
- 关闭重开、切换页面及语言重建不会让旧结果关闭新弹窗或覆盖新输入。重建页面里绑定同一在途操作的按钮会在结束后解除禁用。明确的生成成功使用现有操作通知入口，避免被之前较高优先级的提示遮住。
- 增加生成专用请求编号和有限阶段记录；服务端复用现有日志，浏览器只保留最近一次生成最多 32 条阶段记录。未记录密钥正文、认证头、token 或完整请求体。若只收到错误码且缺少失败阶段及原始原因，保持结果未知，不把响应分配失败误判为生成失败。
- 仅更新 API、应用脚本和语言包缓存标识，保留现有 LPMU 修订。未修改分区、存储格式、全局 HTTP 超时、SSH 信任规则、HTTPS 或其他产品流程。

## 间歇性故障仍待捕获

原来“生成后没有完成反馈”的那一次失败请求没有保留完整记录；调查时的 `testtest` 正常请求不是故障复现。本次完成了已复现存储缺陷修复、反馈合同修正和可定位的诊断，**尚不能认定原间歇性故障根因已解决**。

升级后若再次发生，可结合浏览器 `api.keyGenerationTrace` 中的请求编号、阶段和时间，与设备日志里的 `key.generate request=<编号>` 对照：先判断是否保存，再判断响应构造、发送、浏览器读取/解析、弹窗关闭及列表刷新。发送调用成功不等于浏览器已收到完整响应；缺少一条日志也不能单独证明该阶段未执行。

用户另行刷机后，已授权并完成下方真机验证。本次主机故障注入仍不证明实际 flash 页回收或任意断电恢复，不使用修复前正常记录冒充修复后真机结果。


## 用户刷机后的真机验证

2026 年 10 月 9 日，通过用户 Safari 页面操作设备 `10.10.99.97`。测试前后固件版本均为 `0.6.1+73069d24d.10090640`，ESP-IDF 为 v5.5.2。测试期间没有修改业务代码、删除已有密钥或部署测试公钥。

1. **真实存储不足路径通过。** 对未使用的 `qa1009` 选择 RSA 2048，并双击生成。持续状态出现、生成按钮禁用；浏览器约 1.30 秒收到 HTTP 200、业务码 7。失败阶段为 `private_write`，错误为 `ESP_ERR_NVS_NOT_ENOUGH_SPACE`，后端报告本次清理完成。弹窗和输入保留，具体错误显示，按钮恢复。只有一条生成请求；列表仍为原来的三个 SSH 密钥，NVS 使用条目也仍为 1327。未显示虚假的生成成功。
2. **成功反馈和自动刷新通过。** 不删除原密钥，改用体积较小的 ECDSA P-256，仍使用清理后的 `qa1009`。服务端生成、保存、构造响应及发送全部成功，发送总耗时约 359 毫秒。浏览器约 367 毫秒收到 HTTP 200、`code=0`、`generated=true`；弹窗自动关闭、成功提示出现，约 425 毫秒完成列表刷新，第 4 个 SSH 密钥可见。没有点取消或手动刷新。
3. 原有 `ZJ`、`app`、`testtest` 的 ID、类型、备注、创建时间和导出/隐藏标志保持；`app` 的使用时间随其他实际访问变化。两个已部署主机的记录完整保持。测试密钥 `qa1009` 保留、不可导出私钥、未部署；页面已有 ECDSA 的 SSH 使用限制提示保持。

这次实际结果证明没有固定的“三个 SSH 密钥”数量限制，也证明当前成功和存储失败流程都有完成反馈。**当前设备 NVS 容量问题仍在：RSA 2048 的新私钥未能写入，因此本次没有完成 RSA 生成成功的真机验收。** ECDSA 成功前 NVS 使用率为 87%，成功后为 89%；共享 NVS 的全局剩余条目不能替代某个具体写入是否成功的判断。本次没有扩大分区、清理其他配置或删除原密钥。

另观察到验证前后设备运行时间从 402861 毫秒变为 318219 毫秒，表明期间运行计时发生重置。本次没有重启操作，用户也明确确认没有重启或刷机，重置原因尚未定位；RSA 失败对应的服务端日志未保留，不能用日志缺失推断执行阶段。成功请求的浏览器记录和服务端完整链路已保存，见 [verification.json](../../../output/key-generation-device-20261009/verification.json) 及 [服务端请求记录](../../../output/key-generation-device-20261009/final-system-and-request.json)。此前间歇性无反馈的历史根因仍不能据此定案。
