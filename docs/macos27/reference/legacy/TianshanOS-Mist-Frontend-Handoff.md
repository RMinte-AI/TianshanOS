## 00. 执行摘要与使用方法

本次任务是**在原有天山 OS 产品上实施雾银视觉换肤**，不是用雾银演示站替换天山 OS，也不是重新设计信息架构。保留每个页面、板块、标签页、操作入口、字段、默认值、权限规则及流程；用统一的低饱和灰绿色、实体面板、细线、克制阴影、清晰字体和短时交互过渡，改善使用质感。

用户同时认可玻璃打开和关闭的视觉效果。因此，**实体材质是交付基线；局部玻璃是有条件的视觉增强，不是必须付出性能代价保留的卖点**。主界面天山线条图标必须使用附件中从批准原型提取的原始 SVG，不能重新绘制“差不多”的山形。

执行 AI 的阅读顺序：先读本文件 01–05，建立真实基线；再读 06–16 完成视觉及交互映射；按 17–22 分阶段实施并验证；最后提交 23 所要求的证据。`checks/acceptance-checklist.md` 是逐项验收记录，`templates/` 是待补齐的真实基线模板，`tools/` 是只读辅助检查，不是代替人工审查的证明器。

## 01. 项目范围与禁止事项

### 01.1 允许改动

允许修改颜色、字重、字号、行高、边框、圆角、阴影、间距、对齐、图标表现和视觉状态；允许在原有 DOM 与业务结构内补充必要的样式类、文本包裹节点和非侵入性语义属性；允许修改已存在控件的悬停、焦点、按下等样式。既有动态模板中的硬编码外观，可以逐处映射到语义令牌，但必须保留模板里的真实数据、条件和事件。

允许把重复视觉定义收敛为令牌和样式类。收敛的是样式，不是功能组件、业务事件或页面模块。不能借此合并风扇、存储、设备控制、GPIO 等板块。

### 01.2 明确禁止

禁止删除、合并、改名、跨页迁移板块；禁止用“高级设置”“更多”菜单隐藏原本直接可见的入口；禁止把顶部主导航改为侧栏、底部 Dock 或新层级；禁止把既有模态框改成抽屉、把既有表单改成向导，或更换原来的编辑与保存流程。原本的用户拖拽排序功能与已保存顺序，不能被新的 CSS 排序、重新布局或默认模板覆盖。

禁止修改 API 方法、URL、请求体、参数单位、成功判定、超时重试、认证、权限、设备保护策略、WebSocket 消息和订阅频率。禁止用原型里的演示数据、`setTimeout` 假保存、假连接状态或假终端替换真实流程。禁止修改 ESP-IDF/C/C++、分区、SPIFFS 大小、HTTP 服务、后端缓存策略和硬件控制逻辑。

禁止引入 React/Vue 等新运行时、重型 UI/图表库、图标全量库、外部 CDN、远程字体、分析埋点、Service Worker、新的主题存储机制或新的常驻前端任务。**本期也不新增“玻璃开关”产品入口**：原型开关用于评审，生产是否开启玻璃由受控样式配置决定。基线已经存在的主题/外观功能则必须保留。

### 01.3 发现旧问题时的处理

原有翻译缺失、响应判定、认证、计时器和状态更新问题，先复现并记录为“基线问题”。本次仅修复由换肤引入的问题。旧问题不因本规范而获得修复授权；安全或阻断问题可以阻止发布，但不能被擅自混入视觉改动。提交说明必须分别列出基线遗留问题、新引入且已修复的问题，以及未完成的验证。

原型内 `.navshell`、`.workspace`、`.mist-upper`、`.mist-actionbar` 等只用于解释视觉，不构成生产布局要求。尤其不能把原型底部工具条安装进现有页面并迁走原本按钮。原型的小字号、隐藏规则、装饰背景和玻璃半径也不是必须逐字复制的规范。

原型是一个自包含 HTML，可能保留其他方向的 CSS/JS。**不要把整份文件的 CSS/JS 注入生产，不要把四套设计代码打包进设备。** 只提取经核验的雾银令牌、样式和批准图标。

动态按钮、右键/长按菜单、拖拽手柄、表格行操作、空状态操作、禁用提示和错误后的重试路径都属于库存。默认隐藏但可在某条件下出现的功能不能遗漏。系统无设备、单设备、多设备、断连、不同权限、长列表、语言切换及刷新后持久化至少要各覆盖一次。

**门槛：全部基线库存项都能映射到实施后同一功能，映射比为 100%；不允许多对一合并。** 若某项不能运行验证，标记阻断原因，不能标成通过。

### 04.4 位置微调的边界

同一板块内的内边距、控件对齐与几像素偏移可以调整；桌面默认尽量在原位置周围 8–12 CSS px 范围内解决控件对齐。这是局部评审参考，不是允许跨区域移动的额度。板块上下顺序、父区域、默认展开方式、主要操作所在位置和原有用户排序不变。

因正常文字换行或触控尺寸产生的自然高度变化可以接受，但必须保持信息密度合理，不能把首页扩成多个大面积留白屏。不得为了雾银观感把原本首屏直接可用的高频操作移到页面底部。响应式允许同序自然换行，不允许 CSS `order` 或隐藏列改变业务查找路径。

## 05. 技术路线与改动层级

继续采用原有 HTML/CSS/JavaScript 和构建流程。不要先搭建新框架，再把旧业务迁过去。本次推荐按“令牌映射 → 现有组件外观 → 各页面模板局部 → 状态与三端检查 → 压缩产物回归”的顺序推进。

每项 JavaScript 修改都要归类为：纯样式字符串、保持表达式不变的标记包裹、图表纯显示颜色，或非视觉逻辑。最后一类默认不允许进入本期。不要因为代码很长就重构全局状态、迁移事件、抽象 API 层或更换图表引擎。新增辅助文件优先限于开发测试目录，不应进入设备资源镜像。

主 CSS 和入口关键 CSS 同时存在。两者必须共享同一组基础色值和关键尺寸，避免首次白亮旧主题闪烁、导航跳动或旧变量先渲染。不能靠最后追加几千行 `!important` 解决样式冲突；应逐段查明变量别名、级联、动态模板内联样式和暗色覆盖的关系。[S01][S05]

## 06. 雾银颜色体系

### 06.1 视觉规则

大面积使用雾银灰绿、实体暖白与墨绿文字。强调色只用于真实可交互对象、选中状态或必要重点，不铺满卡片。常态界面保持安静；警告和失败保留明显且准确的语义差异。**界面装饰不得出现紫色、粉色、荧光蓝、蓝紫渐变、多彩霓虹或彩虹 KPI 卡片。**

该禁令仅约束 UI 外观。LED 颜色选择、灯效参数、色轮、校正预览、上传图片、终端 ANSI 颜色及其他用户数据是功能内容，不得去色、替换、截断或映射为灰绿。图表原有类别若重新分配显示颜色，必须保持各系列身份、图例对应及阈值语义，不得通过减色减少系列。

### 06.2 正式浅色令牌

| 令牌（`--ts-mist-` 前缀） | 值 | 用途与限制 |
|---|---|---|
| `bg` | `#E9EEEB` | 页面底色 |
| `surface` | `#FBFCFA` | 卡片、表格、表单、详情等实体内容 |
| `surface-2` | `#F0F3EF` | 输入底、轻分组、非突出背景 |
| `ink` | `#2D3932` | 主要文字与重要数字 |
| `muted` | `#5B6D60` | 可读的次要文字；不是降低整体 opacity |
| `faint-decoration` | `#8B9B90` | 仅装饰或明确不承担信息的部分，不能作普通小字 |
| `line-decoration` | `#DCE5DD` | 卡片装饰边界、非必要分隔线 |
| `line-control` | `#758A7B` | 必须可辨认的输入边界、控件轮廓 |
| `accent` | `#4A6355` | 主操作、焦点、选中图标与链接 |
| `accent-soft` | `#EAF0E7` | 选中或重点区域的轻底色 |
| `success` / `success-soft` | `#4F6856` / `#EAF0E7` | 成功或正常的已有状态 |
| `warning` / `warning-soft` | `#8C5A1E` / `#F5EEE0` | 真实警告，不作装饰主色 |
| `danger` / `danger-soft` | `#A24737` / `#F7EBE7` | 失败、危险和保护异常 |
| `inverse` | `#FBFCFA` | 深色主按钮文字 |
| `glass-solid` | `#F3F7F1` | 玻璃关闭时的实体控制表面 |

原型 `muted=#627468` 在实体面板上可以达到普通文字的最低对比，但在页面底色上约为 **4.24:1**；原型 `faint=#8B9B90` 在实体面板上约为 **2.84:1**。因此正式版将通用次要文字略加深，并把 faint 限定为装饰。它们属于同一雾银色相，不是换成另一套设计。计算方法与结果在 `checks/contrast-calculation.json` 中；透明叠加仍须在浏览器中另测。

### 06.3 既有深色模式不得删除

若基线提供深浅色切换，就必须保留原入口、默认策略、持久化键和选择器。不得把原来承载 `light/dark` 的 `data-theme` 改为 `mist` 导致深色失效；设计版本与颜色模式是两个不同概念。本包给出雾银暗色适配令牌，供保留既有功能使用；**若基线没有深色模式，本期不新增该功能。**

| 令牌 | 暗色适配 |
|---|---|
| bg / surface / surface-2 | `#1D2420` / `#262F29` / `#303A33` |
| ink / muted | `#E9EEEB` / `#B2C0B6` |
| line-decoration / line-control | `#47564B` / `#839889` |
| accent / accent-soft | `#A9C3AD` / `#354A3B` |
| success / warning / danger | `#ACC7B0` / `#D6B77E` / `#E6A69A` |
| inverse / glass-solid | `#1D2420` / `#26312A` |

上述是保持原功能的中性适配，不是把原型石墨方向混入雾银。深色也禁止光晕、霓虹描边和高饱和渐变。图表、终端外壳、弹窗、表单原生选择器与图标均须检测，不能只有首页暗色。

### 06.4 对比度与用色验收

普通文字至少 4.5:1；符合 WCAG 大字定义的文字至少 3:1；必要控件轮廓、状态和图形对象按非文本对比要求至少 3:1。24 CSS px 非粗体或约 18.67 CSS px 粗体是常用的大字尺寸判定边界；不要把 16px 小标题当成大字降低门槛。纯装饰分隔线不强制达到 3:1，但不得用这种例外解释看不见的输入框边界。[S07][S08]

`opacity`、禁用态、hover 底色、遮罩和玻璃背景都会改变实际对比。须验证计算样式和真实背景，不以令牌表代替渲染结果。不得只靠颜色区分告警/成功，继续保留既有图标、文字与状态标签。

## 07. 字体、数字、线条与图标

### 07.1 字体与字号

使用系统字体栈，不下载字体文件：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。这些名字只是本机字体候选；缺少时自然回退，不产生网络请求。不将中文界面改成等宽字体，不用衬线标题、超细字重或大范围全大写来制造风格。

| 内容 | 标准 | 限制 |
|---|---|---|
| 页面标题 | 20–24px，600，行高 1.3–1.4 | 不复制原型 31–39px 的大标题，不改变首屏结构 |
| 板块标题 | 14–16px，600，行高 1.4–1.5 | 同级统一，不以不同颜色区分所有板块 |
| 正文、表单、按钮 | 14px，400/500，行高 1.5–1.6 | 表单移动端输入可用 16px，避免缩放体验问题 |
| 次要说明、表头、状态 | 原则至少 12px，行高 1.45–1.6 | 关键说明不得复制原型 9–10px 小字 |
| 核心指标 | 24–32px，400/500 | 不改变数值精度、单位、空值语义或格式函数 |
| IP、路径、版本、命令、日志 | 既有等宽字体；可用 SFMono/Consolas/Liberation Mono 回退 | 不翻译技术数据，不强制大写 |

数字宜使用 `font-variant-numeric: tabular-nums` 减少抖动；不为动态数字新增“滚动计数”库。不把中文字符做负字距；字距微调限拉丁品牌等少数区域。长英文、文件路径和证书标识使用区域内换行或滚动，不以缩小到难读解决。值与单位的对应关系不变，不能把真实 0 当无数据，也不能把 `--` 填成 0。

### 07.2 线条、圆角与阴影

常规分隔线 1px；必要输入/状态轮廓使用 `line-control`，装饰分隔用 `line-decoration`。卡片半径 18px，紧凑面板 14px，按钮/输入 10px，短状态标签 6px。只有原本圆形按钮或开关采用圆形；不把所有控件做成胶囊。

面板阴影基准 `0 3px 14px #2c453105`，浮层可用 `0 8px 22px #35543b09`。一个内容面板最多一个轻阴影，不做层层卡片、发光描边或巨大的背景模糊。需要强调层级时优先用背景、留白和单条边线，而不是继续叠阴影。所有面板外侧 overflow、拖拽手柄和聚焦轮廓必须可见，不能因圆角裁剪损失操作。

常规功能图标保持既有图标系统，统一显示尺寸约 16–20px、视觉线重相近。不要在同一层级混用彩色 emoji、实心图标和细线图标。原库不能局部调线重时宁可保持原几何，不下载一整套新库；品牌图标例外，严格按下节保留。

### 07.3 天山线条图标：不可重新绘制

下面是批准原型的实际品牌 SVG。`viewBox`、两个 path、各自线宽、连接方式必须保留。不得误用浏览器标签 favicon 的另一个山形，也不得根据描述再生成一个图标。

```html
<svg viewBox="0 0 30 30" fill="none" aria-hidden="true">
  <path d="M3 24 12 6l5 10 3-5 8 13H3Z"
        stroke="currentColor" stroke-width="1.8" stroke-linejoin="round"/>
  <path d="m9 12 3 3 3-3M7 24l7-9 6 9"

```

批准原型的标记容器为约 25×27px，SVG 等比居中。正式版本在既有品牌位置以不挤压导航的尺寸接入；允许等比缩放，禁止拉伸、改山峰比例、统一两条线宽、强加线帽或填充背景。颜色继承当前主题的强调色。品牌文字保留 `TianshanOS`；有相邻可读品牌文字时图形用 `aria-hidden`，防止重复朗读。

仅替换 WebUI 品牌图形，不擅自修改启动图、设备固件品牌、所有 favicon、版权信息或公司署名。保留原 `img` 使用者和尺寸依赖前先查引用；如替换为 SVG 需保留父容器布局契约，不能让旧 `.logo-icon` 尺寸规则误伤。

## 08. 布局与响应式：原位置上的雾银

### 08.1 桌面布局

保留顶部导航、主体内容和已有底部状态区域。采用雾银表面和轻边界，让原位置上的顶部导航看起来更精致，而不是搬成原型中的新悬浮系统。主内容仍利用现有宽度；不擅自将全宽控制台收窄为 1228px 展示站，不新增占据首屏的大设备铭牌或装饰主视觉。

间距使用 4/8/12/16/20/24/32px 序列。页面外边距、面板间距以原布局为基准，优先统一到最近的合理值；卡片内边距通常 16–20px。不要通过把所有卡片放大来“增加高级感”。同一行的标签、输入、单位、错误信息和按钮对齐，但行列归属不改变。

### 08.2 小屏与缩放

至少验证 390、768、1024、1440 CSS px 宽度，并检查 320px 宽度下的可达性、200% 浏览器缩放和手机横屏。视口不是设备物理像素。所有功能必须可用；窄屏可原顺序换行、在原区域内水平滚动或保留既有折叠菜单，不能新增隐蔽入口代替原入口。

表格可以区域内水平滚动，不能删除列或只留下“重要列”；行操作、表头和滚动提示需可见。长命令/证书/路径可以独立滚动，不导致全页横向溢出。手机键盘打开时输入、错误和保存按钮不能被固定栏遮住。若原来固定的顶部或底部元素占位已存在，保留占位机制，不让内容被覆盖。

**不得照抄原型里的 `display:none` 规则。** `.profile-label`、`.service-label small`、导航文本或其他说明在原型被隐藏，并不意味着生产可以隐藏相应内容。只有基线原有的权限/状态可见条件才可决定功能隐藏。

### 08.3 排序与尺寸敏感功能

保留拖拽、用户排序和持久化键。禁止用 CSS `order` 改变视觉顺序而 DOM 顺序未变；禁止用新增 transform 的祖先改变拖拽坐标、弹窗 fixed 定位或终端测量。图表、终端和 LED Canvas 的容器尺寸变化后应通过既有机制适配，不新增常驻尺寸轮询。

## 09. 组件外观与交互状态

### 09.1 按钮与状态提示

主按钮使用强调色背景与反色文字；次按钮使用实体背景、可辨认轮廓；文字按钮保留可点击线索。危险操作使用危险色及明确原文字，不与常规“保存”混同。按钮的 `type`、默认提交行为、权限条件和 disabled 判定不变。

每个按钮检查 normal、hover、focus-visible、active、disabled、已有 loading 六种状态；触屏不能依赖 hover 才能找到操作。原来在请求期间禁用的按钮继续禁用，原来允许取消的操作不能被新的 loading 遮住。请求成功与否继续由原真实结果决定，CSS 完成动画不能触发“已成功”。

已有 Toast、状态条、空状态、错误框、警告横幅统一外观；保留原出现条件、内容、关闭方式和停留策略。不得把持续告警变成三秒消失的提示，不把请求失败转换成空列表，不把最后一次数据改成“实时在线”。新的视觉效果不能吞掉后端错误或翻译后变成无意义的“操作异常”。

### 09.2 表单、开关、滑块

保留所有字段的 `id/name/type/value/min/max/step/required`、绑定数据、校验、默认值、输入格式和提交顺序。样式统一不等于修改字段单位、合并设置项、改 placeholder 含义或改变实时提交/点击保存的区别。

label 与输入保持明确关联；提示和错误在原字段附近，不靠颜色单独表达。密码、地址、端口、数值、选择器、多行文本分别适配，不能全局改变 input 类型。开关“开/关”含义及服务实际状态不变，不能仅凭样式上的 `.active` 决定功能是否开启。

滑块拖动不得由于每次 pointermove 新增设备请求；保留原来节流、提交时机与真实反馈。LED 色轮/矩阵/颜色输入属于内容，不套统一 `filter`、灰度或强调色。禁止给用户颜色值做全局正则替换。

### 09.3 标签页、列表与表格

保留标签数量、名字、顺序、分组和当前项恢复机制。标签标题长时允许换行/原区域滚动，不通过移除文字或改成纯图标解决。选中态同时有文字/轮廓或背景区分；保留既有可点击区域与键盘行为。

列表和表格继续使用原排序、分页、筛选、选中与批量操作；不得为了速度减少结果数量或引入虚拟化改变可见、搜索和选择语义。本期先保持数据结构和渲染范围，仅改善字号、行高、边线、对齐。多设备、多风扇、多规则等重复实体不可折叠成一个汇总卡。

### 09.4 模态框、下拉菜单与其他浮层

保留原弹窗形式、触发入口、按钮顺序、关闭与取消规则，不能一律改成右侧抽屉。关闭按钮不得遮住标题或表单；内容超过屏幕时在原浮层内滚动。确认/取消区保持可见，不让阴影/裁剪遮掉。

不无条件覆盖全局 z-index。先画出原层级表：导航、页面下拉、模态遮罩、模态内容、弹出菜单、提示。新增玻璃会产生层叠上下文，必须验证下拉菜单、终端选择、色轮和文件选择器没有被压住。[S10]

键盘焦点不得因重绘样式跳回页面顶部。既有模态焦点管理若存在必须保留；缺失属于基线问题，不借本次添加新的确认流程。可在保持行为的前提下补充正确 label、dialog 语义与可见 focus，但须逐项验证，不把 `aria-*` 当装饰。

### 09.5 图表、状态栏、终端与特殊预览

优先保留现有图表/SVG/Canvas 实现与函数签名，不引入 ECharts、Chart.js 或新的绘图调度。只映射背景、网格、文字、曲线和阈值状态的显示样式。轴、单位、采样时间、序列数量、历史长度、提示值、点击入口不能改变。平滑、插值、重采样都可能改变含义，本期不新增。

已有底部状态栏不能替换成原型工具 Dock，不能移除 CPU、内存、网络、功率、风扇等原指标。已有帧率/诊断指标如存在必须保留，不因美观藏掉。多个小组件共享旧数据机制，不新增轮询或重复订阅。

终端保留输入、粘贴、中文输入法、快捷键、历史、滚动、选择复制、ANSI 含义、会话断开和尺寸适配。修改外壳、边框和主题适配前先验证终端实测字体宽度；不全局给终端内容应用正文 line-height、letter-spacing 或 transform。日志、文件预览和 LED 图像不套统一的去饱和滤镜。

## 10. 玻璃策略：局部、可降级、不新增产品功能

CSS `backdrop-filter` 是浏览器对背景像素的视觉处理，不是 Apple 原生 Liquid Glass 的完整实现。它的出现不要求 ESP32 做渲染，但会增加特定浏览器上的绘制/合成成本；因此“只用 CSS”不构成性能零成本的证明。Apple 的材质指南也强调在控制/导航层克制使用，而不是铺满内容。[S09][S10]

### 10.1 实施决策

**生产默认关闭玻璃。** 所有内容面板、表格、图表、表单、终端、日志和告警都使用实体背景。只允许对原来就存在的顶部导航/控制表面试验局部玻璃；不得为了玻璃新增 Dock、悬浮工具条、窗口或大面积装饰层。关与开时布局、字号、操作路径必须一致。

原型使用 15px blur 与透明表面。生产试验从更保守的最多 8px blur 开始，提高不透明度：浅色可用 `rgba(243,247,241,.90)`，暗色可用 `rgba(38,49,42,.94)`。不叠加折射、SVG displacement、动态噪声、WebGL、鼠标追光或流体形变。不能动画 blur、filter 或阴影扩散。

### 10.2 支持与降级条件

样式配置只能使用独立的皮肤/视觉标记，不覆盖已有主题或状态属性，不新建 localStorage 偏好。正式是否默认启用，必须在功能、视觉和性能均通过之后明确记录；缺少证据保持关闭。即使启用，也需要以下回退：

| 条件 | 行为 |
|---|---|
| 不支持 `backdrop-filter` | 完全实体背景，无 polyfill |
| `prefers-reduced-transparency: reduce` | 禁止透明与模糊；此媒体特性并非所有浏览器均支持 |
| `forced-colors: active` | 优先系统高对比色与明确边界，禁用玻璃装饰 |
| 本期手机/窄屏基线 | 默认实体，不在弱终端上强求模糊 |
| 性能对照显示可重复回退，或无法验证 | 关闭玻璃，不放宽性能要求 |

对不支持“减少透明度”媒体查询的浏览器，默认实体已经提供可靠结果；不需要用 UA 判断硬件等级、指纹识别或持续 FPS 探测选择材质。单纯 `@supports` 只能说明语法受支持，不能证明速度或可读性。[S10][S11]

### 10.3 流体感的替代

雾银的轻盈主要由细轮廓、略暖实体表面、轻阴影、按钮按压和短暂浮层过渡构成。保留这些即可。原型的大尺寸固定装饰圆环不是正式交付必需项；默认不引入，避免额外绘制和对原布局的干扰。图标也不做呼吸、旋转或漂浮动画。

## 11. 动效规范

只对原有可交互元素增加短暂、可终止的状态过渡：hover 约 120ms，按下约 80ms，浮层出现约 160ms，上限 200ms。优先 opacity 与小幅 transform，且必须验证 transform 不影响定位、图表坐标或拖拽。按钮位移最多约 1px，浮层位移 2–4px；不让业务内容飞入、弹跳或逐项延迟出现。

禁止 `transition: all`、全页循环 animation、数字跑马、装饰性永久 `requestAnimationFrame`、连续轮播和全局 `will-change`。不把现有每秒更新的数据变成每帧数据更新。禁止以动画完毕作为保存成功、开启按钮、关闭会话或路由完成的条件。

新增动效支持 `prefers-reduced-motion: reduce`。只关闭本次新增装饰性动画，不通过粗暴 `* { animation:none !important }` 破坏原本依赖事件或状态的组件。减少动效时功能仍然立即可用；浏览器后台页不保留新增持续动效。[S12]

## 12. i18n：保护实际翻译链，而不是另造一套

### 12.1 以真正的入口为准

参考 `index.html` 的实际链路为：内联建立 `i18n` 与 `t` → 初始化语言 → 动态加载 `js/lang/<code>.js` → `i18n.registerLanguage` 注册 → 翻译 DOM → 切换时重载当前页面。当前入口声明中文和英文。禁止据仓库另有 `i18n.js`，就假定该文件负责运行时；也不能凭残留文件数量增加或删掉可选语言。[S01][S04]

执行者需记录：支持语言表、初始选择规则、存储键、回退规则、动态加载路径与版本、全局函数、事件和当前页重绘机制。若执行分支改变了以上链路，应更新基线说明，不应强迫回退到本文件的参考实现。

### 12.2 不可变契约

保持 `ts_language` 等实际已使用存储键及值格式；保持 `languageChanged` 等真实事件名称；保留设备 `system.language` 同步、登录状态恢复、当前页重绘和原有回退行为。**不得为了减少一次请求而取消设备语言同步，也不得在换肤时再触发一次同步。**

当前运行接口使用 `registerLanguage`、`setLanguage`、`translate`、`translateDOM` 等名字，不能无理由切换另一套 `setLang/updateUI` API。语言加载失败、新建 DOM、重绘、登录后更新这些路径分别测试。已存在的局限（例如切换时某个未保存状态的行为）按基线记录，本次不得引入更严重丢失，也不新增未经授权的离开确认。

### 12.3 文本节点与图标必须隔离

现有 `[data-i18n]` 翻译使用 `textContent`，会替换节点全部子内容。正确模式是把翻译键放在纯文本 span 上，让图标成为兄弟节点。否则中文切换成英文后，新放进去的 SVG/图标可能消失。[S01]

```html
<!-- 示意：只增加必要文本包裹，原事件、参数、type 和权限条件必须保留。 -->
<button type="button" class="btn" onclick="原有函数与原有参数不变">
  <span class="原有图标类" aria-hidden="true"></span>
  <span data-i18n="common.refresh">刷新</span>
</button>
```

此示例不是可直接执行代码，不得把示意 onclick 文本提交到生产。使用 `data-i18n-params` 的动态参数节点须完整保留；不能给带子控件的卡片、label 或按钮外层一律加 `data-i18n`。

当前入口处理 `data-i18n`、`data-i18n-placeholder`、`data-i18n-title`。不要使用并不存在的 `data-i18n-aria-label` 翻译机制后以为已经完成无障碍翻译；优先用可见文字配 `aria-labelledby`，或经现有 t() 路径明确更新必要标签。禁止 CSS `content` 写死新的业务文字。

### 12.4 翻译覆盖范围

检查导航、标题、按钮、字段 label、placeholder、单位说明、校验、表头、空态、错误、确认文本、Toast、连接状态、图表图例/时间范围、文件操作、安全说明、终端外壳、状态栏、可访问名称和动态生成的菜单。不能只检查静态 HTML。

本期原则上不改产品命名，不重写已有整套语言包。新增无损标签或确有授权的缺失 UI 文本，需要在全部**实际启用语言**中同步提供；删除旧 key、把 key 指向不同业务含义、改参数名/类型都禁止。保留 `{name}`、`{count}` 等占位符名字及数量；不用拼接“数量+英文复数”引入新语言逻辑。

技术值不翻译：API 方法、状态枚举原值、配置键、JSON key、设备 ID、文件名/路径、证书内容、指纹、命令、端口、IP/MAC、密钥、日志原文和用户自由文本。显示标签可翻译，发送值不可翻译。若终端帮助内容由设备输出，保留原同步链，不在浏览器擅自改写。

### 12.5 翻译验收

对每种实际启用语言分别完成首启、刷新、直接路由、切换、弹窗、错误、断连、长列表与不同权限测试。验证按钮不截断、表头不遮挡、文本不会让原功能不可达。可用伪本地化/加长字符串作**仅本地测试**，不得进入正式语言菜单或发布包。

检查 `document.documentElement.lang` 与当前语言一致；检查图标、变量数值和登录用户名不会被翻译覆盖；语言切换后当前页面与子标签行为不比基线退步。检查 Network 中语言包没有因重渲染而重复加载，版本串更新一致，没有翻译失败导致裸 key 新增。

静态语言检查只能发现部分问题。`tools/extract_locales.cjs` 可从可信本地语言包导出字典；`handoff_audit.py` 可比较 key、类型、占位符及语言间差异。动态 key、上下文语义、字体截断和注册/加载时序必须人工与浏览器验证。语言文本通过比较，不能证明运行时用的就是那一份包。

## 13. 可访问性与输入兼容

所有已有动作可通过键盘或其原有输入方式完成。保留焦点可见性、Tab 顺序、标签关联和可访问名称；不要移除 outline 而不提供替代。焦点环建议 2px 与 2px offset，必要时补背景隔离；不能被面板 overflow 裁切。

优先采用 40px 左右桌面控件、44px 手机主要触控区域，在不重排模块前提下通过 padding 改善命中。WCAG 2.2 AA 的目标尺寸规则是 24×24 CSS px 或满足其规定例外，**44px 是本项目优选触控目标，不是该 AA 条款的统一硬门槛**。密集技术界面应记录必要例外，不能为了满足一个机械尺寸把全部页面打散。[S13]

测试中文输入法组合输入、英文长文本、键盘 Enter/Escape、复制粘贴、密码自动填充和原生选择器。不要用新快捷键抢占终端或浏览器输入。状态消息不得被高频 `aria-live` 连续播报；新增语义属性需克制，不让每秒刷新变成持续读数。

高对比模式与减少动效/透明度下不丢功能。视觉隐藏文字不能同时删除无障碍名称；禁用操作必须维持原条件，不能因为灰色主题看起来像禁用就让用户误判。

## 14. DOM、CSS 与运行行为契约

### 14.1 冻结选择器和绑定

实施前盘点动态模板、HTML、JS 查询使用的所有 id、data 属性、类、name、事件入口、选择器和父子结构依赖。保留原 ID，不批量改名；同一个页面中不要因复制卡片产生重复 ID。改变文本包裹节点前检查代码是否使用 `parentElement`、`children[n]`、事件委托 `closest()`、拖拽目标或 innerHTML 更新。

保留 `.hidden`、`.active`、连接、错误、权限等真实状态类的业务含义。不能写广义 `.active {…}`、`svg path {…}`、`input {…!important}` 影响所有组件；新增视觉规则优先明确作用域。原来的 `data-requires-root`、路由权限与事件不是可替换的装饰。

### 14.2 样式映射与内联样式迁移

先做“旧变量/类 → 新语义令牌”对照。`--primary`、`--blue-500` 等旧变量有可能被不同语义场景复用，不能看到颜色名就全局替换；尤其检查 LED 与用户颜色值。可以在具体 UI 选择器中使用新令牌，等引用审计完成后再做安全别名映射。

`app.js` 中可能存在模板内联 `style`、公共样式字符串和运行时注入 CSS。按区域逐处处理，保留字符串插值与条件表达式，禁止正则全局替换所有颜色/百分比/像素，也禁止一次格式化整份 app.js。移除旧规则前列出静态引用、动态构造与运行覆盖证据；无法确认的旧 CSS 不以“看起来没用”删除。

### 14.3 加载、缓存和重绘

保留原脚本顺序、defer、按需加载和翻译初始化。主 CSS 与关键 CSS 不出现主题闪烁；缓存版本只按既有 `TS_ASSET_VERSION`/资源版本机制同步更新。不能为美化禁用全部缓存、添加 cache-busting 时间戳、增加 preload 全量脚本或拉取所有语言包。

保留原 API/WebSocket 与路由清理。原先退出页面要停的监视、终端或图表，仍由原路径停止；新视觉逻辑不得包装已有 update 后再执行一轮请求。禁止新增永久 MutationObserver 扫全树、resize 轮询、页面隐藏时常驻动画。需要临时监听则提供严格的注册/销毁对称性，并在重复进出页面验证。

### 14.4 前端安全不退步

不得把原本用 textContent 的用户数据改成 innerHTML；不移除转义、认证 header、CSRF/CORS 相关既有边界、权限禁用或下载校验。用户名、文件名、日志和设备返回错误都视为非可信文本。示例原型的演示 CSP 与真实接口环境不匹配，不能复制其 `connect-src 'none'`，也不能为了兼容 UI 随意放宽生产策略。

测试资料中的 Token、密码、私钥、设备地址等须脱敏；截图不能展示真实密钥。验证脚本不应自动向真实设备执行关机、重启、删文件、写 GPIO、保存保护参数、OTA 或执行 SSH 命令。此类写操作采用可控测试替身，真实设备动作另需明确授权。

## 16. 性能基线与不可回退门槛

### 16.1 比较原则

同一台设备、同一固件后端、同一配置、同一测试数据与客户端环境，只替换前端资源，分别测试 A（实施前）与 B（实施后实体），必要时再测试 C（实施后玻璃）。用户同时进行的后端优化不得混入这组对比；不然不能区分是前端造成开销还是后端消除了开销。

记录浏览器名称/版本、OS、硬件、视口、设备像素比、连接方式、信号/网络条件、缓存状态、打开页数与账号权限。不要仅在开发电脑强 CPU 上观察“不卡”。至少覆盖一个桌面浏览器和一个真实手机浏览器；可用的 Safari、Chromium、Firefox 版本以用户支持范围和执行环境记录，不虚称未测试浏览器兼容。

### 16.2 结构性硬门槛

| 指标 | 门槛 | 证据 |
|---|---|---|
| 新增远程域名/CDN/字体/遥测 | 0 | Network + 构建资源审计 |
| 新增运行时框架、图标/图表依赖 | 0 | 依赖/资源 diff |
| 新增轮询、常驻计时器、永久动画循环 | 0 | 源码审计 + 空闲/后台观察 |
| 业务请求、订阅主题、频率与 payload | 保持基线；不多发、不漏发 | 同场景请求/消息时间线 |
| 并发 WebSocket 与重连机制 | 不改变 | 连接记录与路由循环 |
| 各路由首访必需资源请求数 | 不增加 | 冷缓存网络记录 |
| 各路由/语言首访实际压缩传输总字节 | 不大于基线 | 相同构建选项与冷缓存加载 |
| 发布 Web 资源镜像占用 | 不大于基线，分区与构建方式不变 | 发布构建报告 |
| 缓存后重复访问的静态传输 | 不增加；旧机制继续工作 | 热缓存记录 |
| 新增后台监听、残留 DOM/计时器 | 0 残留 | 重复路由/弹窗后堆与监听检查 |

上述是本项目工程约束，不是行业通用阈值。不能把原型的体积宣称为生产已经达标。资源增加时先收敛本次重复样式、取消非必要装饰；只有证据充分时才能清理确认无引用的旧视觉资源，不能删除功能或减少翻译来“优化”。如果仍无法满足，撤回造成增长的部分并报告，不私自允许增长。

### 16.3 时间与资源指标

比较首屏可用时间、各路由就绪时间、主要交互响应、长任务、绘制/合成、滚动掉帧、前端内存、设备内部堆和 PSRAM 低水位，以及控制操作响应。数值的测量方法、起止点必须一致；不能仅测 DOMContentLoaded 就代表动态页面已经可用。CPU 百分比需说明采样窗口，不能把瞬时读数当稳态结论。

目标是 B 不劣于 A；C 如拟启用也不得劣于 B/A 的相应基线。不存在预先授权的 5% 或 10% 退化额度。结果至少区分 **PASS、FAIL、INCONCLUSIVE、NOT_RUN、BLOCKED**：出现可复现劣化判 FAIL；噪声、缺设备或样本不足不能判 PASS。无回退结论仅限所记录环境和场景，不写“所有设备永远零成本”。

建议以交替 A/B 顺序减少时间漂移，冷启动每端至少 10 次，常见交互累计足够样本后看中位数及 p95；低样本不报告有意义的 p95。至少做一次 30 分钟正常停留与一次 50 次路由/弹窗循环，观察稳定性而非只看首秒。这里的次数是测试方案，不是速度保证；如结果不稳定需补样本，不得凭主观挑选最好的一组。

### 16.4 必测场景

| 场景 | 观察重点 |
|---|---|
| 中文/英文首次打开、资源无缓存 | 总字节、请求并发、资源失败、首次可用、关键样式一致 |
| 重复打开、硬刷新、更新后旧缓存 | 缓存命中、版本一致、不混用旧 CSS/语言 |
| 系统页停留与真实数据更新 | CPU/绘制、数字抖动、图表频率、内存趋势 |
| 在七个原页面间往返、反复开关弹窗 | 重复监听/请求、过期 UI 回写、终端/图表清理 |
| 两个浏览器/标签页同看 | 前端不额外放大原通信行为；后台机制不变 |
| 后台标签页/恢复前台 | 新视觉逻辑不常驻、不出现新增突发请求 |
| 大文件列表、长日志、多设备、多规则 | 排版与滚动无新卡顿，不减少内容或改变分页 |
| 网络慢、断连、返回错误 | 原错误链不变，视觉 loading 不引发自动重试 |
| 手机滚动、打开键盘、改变方向 | 固定层、合成成本、触控与可达性 |
| 玻璃开/关及无支持浏览器 | 布局完全一致；不支持时实体；未通过不启用 |

浏览器 CSS 不由 ESP32 绘制，但更大的静态资源、新网络请求和新计算方式会间接改变设备工作量。本规范要求同时看传输/设备指标与浏览器体验；不能只说“GPU 在电脑上，所以性能不用测”。后端指标仅观察，不为通过测试去修改后端。

## 17. 实施流程与每阶段退出条件

### 阶段 0：冻结、盘点、测量

确认分支和未提交改动；建立全部功能库存、路由/标签/模态/字段列表、选择器契约、语言加载链、主题/存储/排序状态及页面截图。捕获 A 的功能和性能基线。用只读工具生成快照，但同时人工走动态分支。尚未完成上述事项，不开始全面换肤。

退出条件：每个原入口有身份和证据；所有基线异常有记录；性能测量可重复；改动白名单和不可变路径确定。没有实机时可继续本地视觉实现，但应将“设备性能验收”明确置为 BLOCKED，不能进入发布通过状态。

### 阶段 1：令牌、品牌与公共样式

映射浅色/既有暗色令牌，同步入口关键 CSS 与主 CSS；在原品牌位置接入批准 SVG；统一基础文字、边框和控件状态。生产实体材质默认关闭玻璃。先不改任何板块顺序、布局骨架或页面功能。

退出条件：关键 CSS 无闪烁，logo 几何一致，主导航与权限完整，基础对比度通过，首访资源预算未增加，语言切换不掉图标。

### 阶段 2：逐个页面适配

按公共外壳 → 系统 → 网络 → 文件 → 终端 → 自动化 → 指令 → 安全的顺序做小步改动。每页先建立前后局部对照，再调整已识别的视觉模板；每改一页立即跑该页所有库存、状态、语言与小屏用例，不能等全部改完才第一次运行。

退出条件：本页库存 100% 对应、无入口迁移、没有业务逻辑 diff、没有新通信任务、没有操作时序变化。单页不通过不继续复制同一错误到其他页。

### 阶段 3：跨页状态、i18n 与兼容回归

检查登录权限、语言切换、所有弹窗/菜单、主题恢复、拖拽排序、文件/终端/特殊预览、慢网/错误/断连、小屏与键盘。检查不同页面之间共享的 class 和变量没有互相污染。静态翻译比较与浏览器验证同时进行。

退出条件：全部适用语言、权限、主题和关键状态已覆盖；不存在新裸 key、静态中文字、输入丢失或焦点异常；继承的缺陷与新问题清楚分离。

### 阶段 4：可选玻璃与发布产物验证

实体版本通过后才试验局部玻璃。玻璃不通过不阻碍实体版本完成，但不得在发布时悄悄打开。执行真实 minify/gzip/SPIFFS 构建与前后对比，验证关键 CSS、版本串、语言包、字体图标和按需资源都在发布产物里，并且缓存更新仍正常。

退出条件：最终实际发布配置通过功能、视觉、性能、缓存和构建检查；通过的是压缩后真实产物，不只是源文件本地服务器。

### 阶段 5：独立复查与交接

按验收矩阵逐项提供证据；审查完整 diff；输出变更清单、前后入口映射、风险/未测项、恢复说明。不使用“已全部完成”替代记录。可以请另一位 AI 做独立审查，但没有运行证据的复查不能成为通过证明。

本交接本身不授权提交、推送、部署或刷机；是否执行这些写操作由用户在实施会话中另行明确授权。未经授权的实机控制不能作为测试步骤自动执行。

## 18. 检查矩阵与证据格式

完整清单见 `checks/acceptance-checklist.md` 与对应 JSON。每项必须填写结果、环境、步骤、期望、实际和证据路径；默认都是 NOT_RUN。模板中的“期望”不是实测结果。N/A 只适用于真实基线不存在的功能，须附依据，不可用于跳过难测项目。

### 18.1 功能检查

检查七个主入口与原顺序、全部子板块、字段契约、隐藏条件、权限、动作、返回路径、错误状态、保存后的真实结果、用户持久化设置和全部原特殊预览。重点防止“功能还在代码里，但页面上找不到”“按钮还在，但绑定丢了”“数据显示漂亮，但真假状态改变”。

### 18.2 视觉检查

对已映射的代表性 DOM 采集 computed style：背景、文字、边框、圆角、font-family/font-size/font-weight/line-height、阴影与焦点。色值转换为同一格式比较；同一变量名不等于同一实际颜色。截图检查画面秩序、原位置保持、文字截断、线条和图标。SVG 几何使用原 path 对照，而不是只看缩略图。

### 18.3 i18n 与行为检查

实际语言包与运行时支持表相符；字符串 key、类型和占位符无意外变动；原加载和存储行为不变；所有动态区域翻译正确；图标/数据/用户名不被覆盖；语言切换后操作能完成。对已存在但语义不当的翻译记录基线，不凭主题改造直接更改。

### 18.4 性能与资源检查

对每条资源/请求计数给出 A/B 与构建身份；记录具体压缩产物总字节、页面网络消息、CPU/内存/绘制等数据。日志要脱敏。只给“Lighthouse 绿灯”不够；离线设备控制台和真实通信行为还需要本项目场景测试。

### 18.5 自动化辅助的边界

`handoff_audit.py` 为只读标准库脚本：建立文件哈希、源字节及独立 gzip 估计、静态路由/ID/处理器/字段/翻译标记等指纹；比较时将新增/删除/改动列出，并识别默认保护文件变化。它不会执行设备命令、不改源码、不证明所有动态模板都已覆盖。

`extract_locales.cjs` 对本地可信语言包进行受限执行导出。Node 的 vm **不是针对恶意代码的安全边界**；不要对未知或不可信文件运行。该脚本只用于本项目已审查语言资源，不能自动拿它去执行任意下载脚本。浏览器真实加载、重复 key、动态变量和翻译上下文仍需另外检查。

默认受保护 JS 文件的 hash 变化会阻止检查通过；这是对本次范围的保护，不说明变更本身一定错误。需要修改时必须先单独评审范围，而不是删除审计项。app.js/HTML 的视觉改动仍须人工逐行核对所有非视觉逻辑；静态扫描通过不能代替这一步。

## 19. 发布、版本与回滚

保留原构建压缩流程、资源 MIME 和引用机制。修改 CSS/HTML/动态模板时按既有版本机制更新相关引用，`TS_ASSET_VERSION` 与静态资源查询版本保持一致；无需为本次换肤更换为新的哈希路由或 Service Worker。构建后检查每条资源引用都存在、`.gz` 对应内容可解压、所有已支持语言可加载、字体图标与按需终端资源可用。

不要删除旧资源以掩盖错误引用。先确认不再被动态路径、其他页面、缓存或 favicon 使用，再考虑无引用资源清理；本期没有必要时保留。检查源文件与压缩文件是否一致，不允许“开发环境正常，压缩后语法损坏”。当前纯 Python minify 流程对新语法的兼容性需要实测，不直接引入未经验证的新 JS 语法。

准备回滚所需的前端源快照、原资源版本和构建产物标识。回滚只撤回本次视觉改动，不覆盖用户同期后端修复、不重置配置、不清除用户语言/排序/主题存储。任何部署/刷机步骤需要授权并使用现有项目流程；本规范不提供自动真实设备控制脚本。

## 20. 风险清单与处置

| 风险 | 识别信号 | 处理方式 |
|---|---|---|
| 原型覆盖生产 | 演示数据、review bar、假保存或新功能结构出现在 diff | 立即撤回覆盖，回到原模板局部换肤 |
| 颜色替换误伤 LED/数据 | 灯效参数、色轮、图像或 ANSI 变灰绿 | 恢复功能数据，只改 UI 外壳 |
| 内联关键 CSS 与主 CSS 不一致 | 首屏旧色闪烁、导航高度跳变 | 对照令牌与加载阶段逐项修正 |
| i18n 改错入口 | 改了未使用文件，真实界面不变；或加载两套运行时 | 以 index 与 Network 为准，保留原链 |
| 翻译清空图标/控件 | 切换语言后按钮只剩文字、值消失 | 改为兄弟文本 span，保护 data-i18n 边界 |
| 新样式碰撞旧状态类 | 隐藏/禁用/权限类表现异常 | 明确作用域，恢复原状态语义 |
| 玻璃层挡住交互 | 下拉被盖、固定层错位、触控不响应 | 取消玻璃/祖先 transform，恢复层级 |
| 本地存储与主题破坏 | 刷新后排序/语言/主题丢失 | 保留原键和值，不复制原型状态机 |
| 异常被美化掩盖 | 红色警示消失、断连显示在线、失败变成功 | 恢复真实状态链，禁止再解释为设计取舍 |
| 为控大小删功能 | 删除低频页面/语言/字段、隐藏表格列 | 立即判功能验收失败 |
| 性能无法判定 | 缺实机、环境不同、样本噪声大 | 标记 BLOCKED/INCONCLUSIVE，不能宣称通过 |
| 并行改动混入 | 同一 diff 出现服务器/保护/协议修改 | 分离改动，前端范围重新对比，不覆写别人代码 |

## 21. 完成定义：必须同时成立

**功能等价、位置保持、雾银一致、翻译完整、性能不退步、真实产物可运行**六项同时成立，才可认定完成。不能用其中一项补偿另一项：更漂亮不能补偿入口消失；更快不能补偿删功能；测试通过不能补偿用户不认可的整体大改；玻璃好看不能补偿掉帧。

每个基线功能库存项必须有实施后对应证据；全部适用关键验收项应 PASS，N/A 需证据；存在 FAIL、关键 NOT_RUN/BLOCKED 或未解除的 INCONCLUSIVE，不能宣布达到最终发布标准。无实机时可以报告“前端实现与模拟回归已完成，设备性能验收尚未完成”，不能写“已经确保不影响 ESP32”。

交付中必须明确玻璃的最终默认状态。用户没有要求一定开启，因此在约束下交付实体雾银是正确结果，不是未完成视觉要求。天山线条标记、色相、细线与实体材质仍须保真。

## 22. 评审方法与停止条件

每一批次的 diff 要回答四个问题：改了哪些视觉属性？有没有改变条件、数据和事件？有没有让原功能换地方/隐藏？有没有增加资源、请求或常驻计算？无法回答的改动先拆小，不继续堆叠。

以下情况应停止扩大改动：发现参考与当前分支不一致但未重新盘点；准备改业务逻辑才能适配设计；准备移走/合并板块；想用新框架快速重写；真实功能库存尚有缺口；关键性能无法度量；演示文件被直接覆盖进源码。停止意味着保留已完成的合规成果并报告具体缺口，不意味着自动换一套更简单的产品。

问题分级建议：P0 为误执行/权限/保护含义或数据安全问题，立即阻断；P1 为功能不可达、语义改变、性能回退、翻译/资源加载阻断；P2 为局部视觉规范或低频兼容问题。不能把“按钮被藏起来”归为低优先级审美问题。

## 23. 执行 AI 的最终交付格式

最终报告至少包含以下内容，各节附证据文件，不只写完成感言：

| 交付项 | 内容 |
|---|---|
| 变更摘要 | 实施 HEAD、改动路径、各页视觉改动、玻璃默认状态 |
| 功能保留证明 | 完整基线库存与一对一映射、原位置前后截图、权限/流程结果 |

| 性能对比 | A/B 环境、实际构建与传输字节、请求/订阅、时延/内存/绘制、玻璃对照 |
