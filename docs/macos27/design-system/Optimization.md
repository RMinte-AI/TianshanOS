# 优化方向

这一节是下一轮视觉优化的输入。前两部分来自仓库文档和我读取样式表的结果，第三部分是建议的做法。

## 一、仓库里已登记的问题

`docs/macos27/DEFECT-REGISTER-20260929.md` 登记了 20 项审查发现（V01–V20，P1 共 10 项、P2 共 10 项）。状态以该台账为准，本系统不代表它们已关闭。按主题归类：

| 主题 | 编号 | 要点 |
|---|---|---|
| 按钮角色 | V01, V02 | 主、次操作同为白按钮；几乎所有按钮都做成胶囊 |
| 表格 | V03, V04 | 安全页表格操作列拥挤，外框与列宽脱节，空态底框不完整 |
| 表单与设置行 | V05, V10, V13 | 密码输入与操作相距过远；时区行控件不协调；图标、文字、控件基线不一致 |
| 页面排版 | V06, V11, V12 | 安全页模块间距割裂；同级标题字号字重漂移；数值、标签、徽章过度强调 |
| 弹窗 | V07, V08, V09, V20 | 上白下彩断层；头、身、底结构不统一；长弹窗滚动与主操作定位；样式作用域可能不命中 body 挂载的浮层 |
| 色彩 | V14, V15, V16 | 多套蓝色混用；红绿橙沿用旧色阶；状态整行整卡染色过多 |
| 层级与容器 | V17, V18, V19 | 嵌套卡片、边框、阴影重复；标签页与分段选择器风格零散；玻璃高光阴影过重 |

## 二、读取样式表时的发现

以下都是我对 `style.css` 和 `index.html` 的直接观察，不是台账内容。

1. **蓝色有三套并行**：`--blue-500 / --primary-color`（#3b82f6，分别约 52、31 处引用）、`--ui-accent-text`（#0064d2，约 24 处）、`--ui-accent`（#007aff）。这正是 V14 的来源。建议收敛到 `accent` 和 `accent-text` 两个语义，旧名保留为别名再逐步替换。
2. **别名层叠**：`--text-color → --text-primary`、`--bg-color → --bg-muted`、`--bg-hover`、`--bg-tertiary` 全都指向同一个 `--bg-muted`。多个别名只是历史命名，并不表达不同含义。
3. **状态样式重复定义**：`.status-badge` 在样式表里定义了两处（约 1359 行和 4792 行），`.status-dot` 也是两处（约 3487 行和 3737 行）。另有 `.status`、`.badge` 两套做同一件事。建议合并为一个状态胶囊组件。
4. **圆角令牌不完整**：定义了 9 / 12 / 20px，但顶栏和内容面用硬编码 23px，弹窗 27px，文件列表 16px，徽章 6px。已在本系统补上 `radius-shell` 和 `radius-modal`，文件列表和徽章仍是硬编码。
5. **没有间距令牌**：卡片 20px、内容面 26px、页面留白 24px 全靠硬编码。
6. **只有浅色主题**：样式表里没有 `prefers-color-scheme` 分支，只有 forced-colors、reduced-motion 和 hover 相关的媒体查询。
7. **样式表规模**：`style.css` 约 7900 行，其中 `:root` 只有一部分令牌，另一部分写在 `index.html` 关键 CSS 里，令牌来源分散。

## 三、建议的做法

- **先动令牌，再动页面。** 把令牌合并成一份来源，旧名做别名。这一步基本不改视觉，风险最低，也最容易验证。
- **体积是硬约束。** 当前实施结果比原版多 11KiB，SPIFFS 零增长验收 FAIL，尚待决定是否接受。令牌整理应同时删除重复规则，把这部分体积抵回去。
- **视觉探索在 Design 里做，落地在 CLI 里做。** 基于本系统出几个方向的页面稿（例如安全页、系统页），选定后再交给 Claude Code 在 `feat/macos27-webui` 分支上实现，并跑 `tests/macos27` 回归。
- **优先处理的三项：** V01/V02（按钮角色）、V14–V16（色彩语义）、V17（嵌套容器）。这三项能被令牌直接表达，本系统里的 Button、Status、Card 组件就是它们的目标形态。
