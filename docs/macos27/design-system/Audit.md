# macOS 细节审查

方法：用仓库自带的本地夹具（不连设备）在 Chromium 里渲染生产 WebUI，1440×1000、2 倍像素，覆盖系统、网络、文件、自动化、指令、安全、OTA 七页，另测内存弹窗、语言菜单和键盘焦点，并读取 174 个按钮和 17 个输入框的实际计算样式。

限制：截图环境是 Linux 上的 Chromium，字体不是 SF Pro 和苹方，所以字重和字形的观感判断不作数，只有测得的数值可靠。页面数据是夹具数据。我没有测悬停、按下、动画，也没有在 Safari 和真机上验证。

## 二、材质（Liquid Glass）

实测参数：

| 表面 | 背景 | 模糊 | 饱和度 |
|---|---|---|---|
| 顶栏 | 白 0.44 到 0.19 渐变 | 22px | 1.35 |
| 语言菜单 | 白 0.44 到 0.22 渐变 | 18px | 1.45 |
| 弹窗 | 纯白 0.78 | 18px | 1.15 |
| 导航胶囊 | 纯白 0.40 | 无 | 无 |
| 主内容面 | 纯白 0.93 | 无 | 无 |

问题：

1. 三种玻璃三套参数，没有统一的材质等级。
2. 主内容面 93% 不透明且无模糊，壁纸基本透不出来，整页看起来是"一块白板贴在壁纸上"，而不是分层的半透明材质。
3. 弹窗用纯白 0.78，遮罩却是 50% 黑。白玻璃叠在半黑遮罩上，得到的是发灰的雾面，不是通透的亮玻璃。macOS 的 sheet 只把背景轻微压暗。
4. 没有高光边缘的层次：只有一条 1px 白描边加顶部内高光，缺少 macOS 那种边缘折射的亮暗渐变。
5. 导航胶囊是平的半透明白，没有内部深度。

## 三、按钮

![系统页](/_blob/8b24b77e9c25609c79f7886cab386d24)

- 同一张卡片头里，「服务 2 / 2」、「关机设置」、「USB: AGX」、「重启」的高度、内边距和图标间距各不相同；相邻的「同步时间」「时区」又是另一档。
- 一个视图里同时有三种形状：9px 圆角矩形按钮、50% 圆形图标按钮、胶囊状态。状态胶囊（「AGX 已关闭」「网络可达」）和按钮并排，看起来都能点。
- 「测试」是橙色淡底，紧挨白色的「清除测试」。语义色被当成装饰使用，橙色在这里并不表示告警。
- 顶栏的「退出登录」是白色矩形，与旁边的导航胶囊、语言按钮不属于同一套形状。
- 安全页：「设置 root 新密码」按钮高约 34px，同一行输入框约 40px，两者是底对齐，按钮顶部比输入框矮一截。同一行的控件应同高。

![安全页](/_blob/83c125ff022ba0420baa6eb103cc1797)

- 表格操作列 5 个动作有 3 种外观：公钥、私钥、部署是白边，撤销是橙色淡底，删除是红色淡底。图标风格也不一致，有填充有线性。
- 表格里 HTTPS 那一行整行铺了琥珀色背景（缺陷 V16）。

## 四、颜色

- 进度条用绿色 `#10b981`，其余强调都是蓝色，进度条与主色脱节。
- 弹窗里的数值随意着色：红、橙、绿、深红加粗，另有一条紫色进度条；圆环一红一橙。颜色在这里没有稳定含义。
- 状态点、胶囊、按钮各用一套红绿，深浅不同。
- 游离色见上表「文字色」一行，应是旧色阶里漏网的硬编码值，我没有逐个追到源码行。

## 五、排版

- 标签后面带冒号：「芯片:」「Core 0:」「DRAM:」。macOS 的标签不带冒号。
- 值换行破坏对齐：「固件」一行里 `BASELINE-FIXTURE / 5.5.2` 的斜杠被挤到下一行行首；「输入电压」下面的 `/ 内部 19.20 V` 也是同样的孤立斜杠。
- 24 种字号，且大小落差不成比例：卡片标题 15px，风扇转速主值 56px，中间缺少过渡角色。
- 数字列没有统一使用等宽数字，百分比和单位对不齐。

## 六、焦点和菜单

![焦点环](/_blob/8fa6989d3658567759ad8b22ce5dba31)

- 焦点环是 2px 实心 `#0064d2` 描边，紧贴并略大于导航胶囊，颜色很重。macOS 用较粗的半透明强调色外发光环，与元素同形。

![语言菜单](/_blob/e03e7e3bc0674cccdf1601ceb1a4651d)

- 语言菜单压在顶栏和下方卡片标题上，透出重叠文字，层级不清。
- 选中项是蓝字加文字符号 ✓，选中行用灰带；macOS 菜单选中是整行强调色高亮，勾选用 SF Symbols 的 checkmark。
- 菜单宽度等于触发按钮宽度，项高和内边距偏大。
- 触发按钮上的「▼」是文字三角，不是系统的 chevron。

## 七、图标

- 图标来自 Remix Icon，填充和线性混用（⊕ 填充，电源线性），粗细不统一。macOS 用单一字重的 SF Symbols。
- 卡片标题前的灰色渐变方块图标底，语义弱，占位大。

## 八、容器

- 弹窗内又套了多层卡片（静态内存、IRAM、RTC），玻璃里再放灰底卡片，再放数值格（缺陷 V17）。表头是一条白色横条，与下方无底色的表体反差大。
- 弹窗标题没有独立的顶栏区域，与关闭按钮之间没有材质分隔，关闭按钮只是一个 × 字符。

## 九、建议的规范（待你确认）

这些是我基于上述测量提出的起点，数值需要你定：

1. **控件三档**：小 28、常规 32、大 40px；同一档内高度、圆角、字号、内边距相同。输入框与按钮同档同高。
2. **形状只留三种**：矩形圆角（按钮、输入）、圆形（图标按钮）、胶囊（导航、状态）。状态与按钮做明显区分（状态不带边框、不带阴影）。
3. **按钮角色**：主（蓝底白字）、次（白底）、危险（淡红底）。其余语义色只用于状态，不用于按钮装饰。
4. **材质三级**：栏（顶栏、导航）、面（主内容）、浮层（弹窗、菜单）。每级一套模糊、饱和度、不透明度和边缘高光；遮罩改为轻压暗。
5. **颜色收敛**：一个强调蓝，一套红绿橙，游离色全部清掉；数据可视化另建一组调色，不与状态色混用。
6. **字号角色**：标题、副标题、正文、标签、说明、数值 六到八个。
7. **焦点环**：半透明强调色外发光环，与元素同形。
8. **标签去冒号，值不断行，斜杠单位与数值同行。**

## 十一、圆角与同心

实测圆角有 19 种，且相邻层级互不对应。例如主内容面 23px、卡片 20px、边距 24px，卡片内圆角应约为 0，实际却是 20px。

Apple 在 WWDC25「Get to know the new design system」里给出的形状规则：

- 同心形状：内圆角 = 外圆角 − 边距。
- 胶囊：圆角 = 容器高度的一半。
- 固定形状：圆角是常量；边距大于外圆角时，同心形状用一个固定值兜底。
- macOS 和 iOS 上，迷你、小、中号控件保持圆角矩形，大号控件改用胶囊。

据此推出的目标圆角（数值是我的取值，规则来自 Apple）：

| 元素 | 圆角 | 推导 |
|---|---|---|
| 主内容面 | 32 | 固定 |
| 卡片 | 16 | 32 − 边距 16 |
| 卡片内小块 | 12 | 边距大于半径，用固定值 |
| 顶栏 | 30 | 胶囊，高 60 的一半 |
| 导航轨道 | 20 | 30 − 边距 10 |
| 导航项 | 16 | 20 − 边距 4 |
| 分段轨道 / 滑块 | 10 / 8 | 10 − 边距 2 |
| 菜单 / 菜单项 | 16 / 10 | 16 − 边距 6 |
| 按钮 小 / 常规 / 大 | 8 / 10 / 胶囊 | 圆角矩形，大号为胶囊 |

## 十二、必须保留的功能

优化只改样式，不能改功能。审查中我曾把三处可点击控件画成了纯文字，已纠正：

- AGX 电源键（`toggleAgxPower`）：点击开关机，文字显示当前状态。
- LPMU 电源键（`toggleLpmuPower`）：点击触发电源脉冲，文字显示网络可达状态。
- 保护开关（`toggleProtection`）：点击切换保护。

落地前需要对每个页面逐个核对 `onclick` 处理函数，做成功能清单。

## 十三、macOS 27 对照审查（整体）

macOS 27 的公开变化【来源：WWDC26 报道，见回复中的链接】：所有 App 使用统一的窗口圆角；设置里新增玻璃透明度滑块（从超透明到更多着色）；顶部统一的磨砂工具栏回归；侧边栏延伸到窗口边缘，彩色图标只在 App 处于活动状态时显示。以下是我对画布稿逐项对照后发现的问题，按重要程度排序。「已改」表示已经落在画布或令牌里，「待确认」是会改变你已经满意的外观，需要你点头。

**一、对比度（已改）**
- 次要文字色 `#7a828c` 在卡片底色上只有 3.2–3.9:1，低于 4.5:1。改为 `#5f6670`（卡片底色上 4.8:1 以上）。
- 成功文字色 `#1d7b36` 在卡片底色上 4.45:1，略低。改为 `#187030`（5.1:1 以上）。
- 数值是我按 WCAG 相对亮度公式算的，不是设计工具截图。

**二、与 macOS 惯例不一致（已按你的确认全部落地）**
1. 导航选中项用实心蓝底。macOS 的分段控件和标签栏选中态是白色（玻璃）滑块，蓝色留给默认按钮。建议导航选中改成与 `.seg` 相同的白色滑块，这样全站只有「主操作」是蓝色。
2. 弹窗右上角有圆形关闭按钮，同时底部又有「取消」。macOS 的表单类 sheet 没有 ✕，靠取消和 Esc 关闭。建议：有取消按钮的弹窗去掉 ✕，只读弹窗（如内存详情）保留。
3. 按钮悬停光标用手型。macOS 原生按钮保持箭头，只有链接是手型。建议 `button { cursor: default }`。
4. 顶栏是悬浮胶囊。macOS 27 强调统一的磨砂工具栏。网页里悬浮胶囊仍然合理，但建议内容从下方滚过时加「滚动边缘」渐隐，并把顶栏底色从 0.50 提到 0.60，保证按钮可读。
5. 图标描边 1.5px、16px。SF Symbols 在 13pt 常规字重下线条更细，约 1.25px。建议 1.3–1.4，并与文字基线对齐。

**三、画布稿里缺失的状态（悬停、选中、按下、焦点、禁用、加载已在「菜单、提示与状态」板补上；空状态、Toast 也已补；单选框和菜单弹出后的完整样式未做）**
- 表格行的悬停和选中态（macOS 列表选中是主色 15% 的圆角行，内缩 4px）。
- 禁用态（文字用次要色，控件整体 40% 不透明度）。
- 按下态（按钮加深，不缩放）。
- 键盘焦点环只在规范里定义了，页面稿里没有画出。
- 空状态、加载中、错误提示（Toast）的统一样式。
- 单选框，以及下拉菜单弹出后的样式（菜单是 16px 圆角浮层，项 10px）。

**四、字体大小**
macOS 原生控件默认 13pt。画布用 14px 正文是为了网页可读性，这是有意取舍；如果你想更「原生」，可以把正文降到 13px，控件高度不变。我建议保持 14px。

**五、动效（规范里缺）**
弹窗用「淡入 + 由 0.96 放大到 1」，180–240ms，`cubic-bezier(0.2, 0.8, 0.2, 1)`；开关、分段滑块用同一曲线滑动；`prefers-reduced-motion` 下改为纯淡入。

**六、不需要改的**
圆角同心规则、控件三档高度、状态与按钮分离、三级材质、24px 的页面边距，已符合 macOS 26/27 的方向。

**七、系统主色**
我记得 iOS/macOS 26 的系统蓝在浅色下从 `#007aff` 调整为 `#0088ff`，但没有查到 Apple 官方色值页确认，所以画布仍用 `#007aff`。需要对齐的话请以 Apple 官方色值为准。

## 十四、功能覆盖清单

画布共 16 个板：系统、内存详情、系统页弹窗、网络、文件、终端、自动化、指令、固件升级、安全、控件与材质规范、其它弹窗、自动化弹窗、LED·网络·日志·登录弹窗、安全页弹窗、菜单提示与状态。

弹窗模式：**A 确认**（≤420px，取消 + 主操作）、**B 表单**（460–720px）、**C 大型**（≥760px，正文可滚动）、**D 菜单**（16px 圆角浮层，项 10px）。

字段来源：全部弹窗的字段和按钮都是从 `app.js` / `index.html` 读出来的（含数据源四种类型、动作模板六种类型、指令编辑的展开选项、生成密钥对、主机指纹不匹配、导入 SSH 主机）。仍需落地时核对的只有：文件选择器的空状态文案，以及「LED 控制」动作里随控制类型变化的参数（只画了控制类型，没有逐种画参数）。

## 十六、红色预算

问题：安全页表格里撤销、删除、故障状态同时用红色，整页多处红色抢眼。规则：

- 破坏性按钮（删除、撤销、卸载等）平时是中性灰，悬停才变红。
- 红色只出现在三处：确认弹窗的主按钮、故障状态、校验错误。
- 一个视图内最多一个红色元素；确认弹窗一次只出现一个，因此不冲突。
- 「不可撤销」与「可恢复」的区分见 `NativeDialogs.md`：前者主按钮红，后者主按钮中性。

## 十七、分组表单

LED 弹窗原稿混乱的原因：同一个弹窗里「上标签下输入框」、行内散排、独立蓝色按钮混用，三个蓝色主按钮同时出现，控件宽度参差。新规范：

- 一个圆角分组（12px，白 62%）放若干**行**，每行 46px，左侧标签（可带 12px 说明），右侧控件，行间 1px 发丝线。
- 分组标题在分组上方，13px 次要色。
- 每个弹窗只有**一个主按钮**，放在底部；不再在正文里放蓝色按钮。
- 顶层标签用整宽分段控件，各段等宽；二级切换（图像 / QR 码）居中放在标签下方，一次只显示一个功能。
- 三个以内的互斥选项用分段控件，不用下拉框（如文本对齐）。
- 被开关控制的行在关闭时变灰（如「自动位置」打开时 X、Y 不可用）。
- 长文本输入（命令、PEM、URL）仍用上标签的整宽输入框。

## 十五、原样保留 / 有意改变

- 「已启用 / 已禁用」原来是可点的胶囊，改成开关，功能不变（`toggleSource`、`toggleRule`）。
- 「网络可达」改为「LPMU 电源 在线」，含义不变：状态仍只来自可达性判断，不代表真实电源状态。
