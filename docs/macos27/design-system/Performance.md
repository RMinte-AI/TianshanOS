# 性能规范

目标：在最好看的界面下，把设备（ESP32-S3）和浏览器两侧的开销压到最低。渲染由浏览器完成，所以设备侧成本主要是**字节数、连接数、请求频率**，浏览器侧成本主要是**合成层和重绘**。

> 标注约定：【实测】来自仓库静态文件或本地 fixture 服务（`?state=populated`），不代表真机；【估算】是我的推算；【待核】需要你在真机或 sdkconfig 上确认。

## 一、基线（【实测】，分支 feat/macos27-webui）

| 项 | 数值 |
|---|---|
| `css/style.css` | 155,922 B，gzip 27,639 B |
| `js/app.js` | 1,131,592 B，gzip 211,107 B |
| `js/api.js` | 36,638 B，gzip 8,963 B |
| `index.html` | 31,603 B，gzip 8,664 B |
| `fonts/remixicon.woff2` + `.css` | 189,216 B + 5,940 B |
| `js/lang/` | 352 KB（目录合计，含多语言） |
| SPIFFS 占用 | 约 2.6 MB / 3 MiB，此前零增长检查已超 +11 KiB |
| 系统页首屏请求数（fixture） | 32 |
| 系统页稳态请求（fixture，20 秒） | 6 个，`automation/variables/list` ×4、`device/ping` ×2 |
| 系统页 DOM 节点（fixture） | 640 |
| 页面上可见的 `backdrop-filter` 元素 | 0（仅弹窗、语言菜单声明了，未显示时尺寸为 0） |

代码里的定时器（【实测】读 `app.js`）：设备状态 10 s、LPMU 轮询、组件刷新默认 5 s、网络页 LPMU 接入 1.5 s、OTA 进度 1 s、日志跟踪 2 s、本地时钟 1 s（纯前端）。各自独立创建，没有统一调度。

## 二、原则

1. **零净增长**：新规范上线后，`web/` 总字节数不得高于基线。视觉升级靠删旧换新，不靠加文件。
2. **能不用就不用，用了就有预算**：每个耗资源的视觉特性都要有出处（这里的效果换来了什么）和上限。
3. **设备只做必要的事**：浏览器能算的不让设备算；能推送的不轮询；不可见就不请求。

## 三、字节预算

| 目标 | 做法 | 预期 |
|---|---|---|
| 图标 | 用一份内联 SVG sprite（16px，描边 1.5）替换 Remix Icon 字体，只保留实际用到的图标 | 释放约 170 KB【估算，取决于图标数；图标字体是「混用填充和线性」的根源，顺带解决】 |
| 字体 | 只用系统字体栈，不内嵌任何网页字体 | 0 字节 |
| 品牌字标 | 画布里的 TianshanOS 字标是把 Quantify Bold 轮廓转成 SVG 路径（约 4 KB，未做字距微调）。不内嵌 Quantify 字体文件 | 约 4 KB；【待核】授权是否允许把字形转成矢量 |
| 壁纸 | 纯 CSS 渐变，不用图片 | 0 字节 |
| CSS | 语义令牌 + 三级材质 + 三档控件，删除三套蓝色、重复的按钮定义 | 目标 gzip ≤ 27.6 KB，不高于基线 |
| JS | 按页面拆分，进入页面时才加载；语言包只加载当前语言 | 首屏 JS 下降；【待核】现有是否已按需加载 |
| 传输 | 预压缩 `.gz`；带内容哈希的文件名 + `Cache-Control: max-age=31536000, immutable`；`ETag` | 回访 0 字节；【待核】固件当前是否发送缓存头 |

## 四、连接与请求预算

- 首屏请求数目标 ≤ 12（基线 32）：合并 CSS/JS、SVG sprite 内联到 HTML、去掉小图标 PNG 的多尺寸引用。
- 客户端同时进行的 fetch ≤ 4，用队列串行化。`esp_http_server` 的并发套接字数量有限，默认值约 7，【待核】以你们 sdkconfig 为准。
- HTTP/1.1 keep-alive，页面内复用同一连接。
- **统一调度器**：全站只有一个轮询入口。规则：
  - 页面不可见（`document.hidden`）时暂停；
  - 只请求当前页面用得到的数据；
  - 稳态目标 ≤ 1 个请求 / 2 秒（当前 fixture 约 0.3 个 / 秒，真机数据可能更多，【待核】）；
  - 失败时指数退避，最长 30 秒；
  - 优先复用已有的 WebSocket（`api.js` 已有），把状态改成推送。
- 【待核】若固件可提供一个聚合的状态端点（电源、温度、风扇、LPMU 一次返回），可以把多个轮询合成一个。这是固件改动，不在 UI 规范范围内，列为后续建议。

## 五、渲染预算（浏览器侧）

关键判断：**壁纸是平滑渐变，对它做背景模糊看不出效果**，模糊只在下方有细节内容的地方才有意义。据此：

| 层 | 是否使用 `backdrop-filter` | 理由 |
|---|---|---|
| 主内容面（约 1392×1200，最大的一块） | **不用**。用半透明白 + 静态渐变即可，视觉上等价 | 面积最大，成本最高，且下方只有渐变 |
| 顶栏 | 用，`blur(24px) saturate(1.8)` | 内容会从下方滚过，这是玻璃质感最明显的地方 |
| 弹窗 / 菜单 | 用，`blur(44px) saturate(1.9)`，同一时刻最多一层 | 下方是页面细节 |

- 同时存在的 `backdrop-filter` 层 ≤ 2（顶栏 + 一个弹窗或菜单）。
- 模糊半径 ≤ 44px；不使用 `filter: drop-shadow`，阴影最多两层。
- 动效只动 `transform` 和 `opacity`，时长 180–240ms，不动画 `box-shadow`、`width`、`height`、`backdrop-filter`。
- 屏外区块用 `content-visibility: auto` 加 `contain-intrinsic-size`（LED 区、安全页各表格）；卡片加 `contain: layout paint`。
- 单页 DOM ≤ 1500 个节点（当前系统页 640，【实测】）；表格或日志超过 200 行时做窗口化渲染。
- 轮询数据只更新文本节点，不整块重写 `innerHTML`；【待核】现有 `app.js` 哪些位置在整块重绘，需要逐处检查。
- 壁纸放在一个固定定位的伪元素上，只绘制一次，滚动时不重绘。

## 六、材质档位（同时是性能开关）

macOS 27 已加入用户可调的玻璃透明度滑块（见 Audit 十三），所以设置一个「界面材质」选项，一举两得：

| 档位 | 表现 | 代价 |
|---|---|---|
| 清透 | 顶栏与弹窗更透，饱和度 1.9 | 最高 |
| 标准（默认） | 规范里的三级材质 | 中 |
| 实心 | 全部改实色，不用 `backdrop-filter` | 最低 |

实现：一个 CSS 变量 `--glass-a` 与一个 `data-material` 属性，选择存 `localStorage`。用户系统开启「减少透明度」时默认选「实心」（`prefers-reduced-transparency`，浏览器支持情况【待核】）。

## 七、验收方式

- 在现有 `tests/macos27/` 加一个预算测试：读取 `web/` 的 gzip 后字节数与请求数，超过本页数值即失败。
- 首屏请求数、稳态请求频率用 Playwright 在 fixture 上统计（本页数字就是这样得到的）。
- 真机复测由你在设备上做：至少测首屏加载时间和 20 秒稳态请求，因为 fixture 不能反映 ESP32 的响应速度。
