## 必须落地的视觉规范

### 字体与控件

使用本机系统字体栈，不下载 SF 字体。先形成简短的角色表：页面标题、分组标题、弹窗标题、正文/表单、说明/技术文字、数值/单位、普通/紧凑按钮，明确字号、字重、行高和间距，落到实际控件。

正文/表单以 14px 为起点，次要/技术文字至少 12px，分组标题约 15–16px，页面/主要弹窗标题按角色约 20–25px；具体值以实机观感和可读性验证，不机械套用每一个窗口。数字适当轻字重、等宽数字，保留单位和精度。原生 API 默认 13pt 不是所有网页文字的强制值，Retina 像素不是 CSS px。

明确 px/rem/em 的基准，不通过全局改根字号造成其他控件尺寸连锁漂移。读取实际 computed style 检查，不以 CSS 中写了令牌证明命中。

按主、次、危险、工具、行内、禁用角色逐入口配按钮。正常提交主操作明确，取消保持次级；危险确认保持危险语义。普通控件可用 8–12px 圆角，紧凑导航/适合的控制可用胶囊，不能全部胶囊化。统一同类高度、图标尺寸、基线与状态，不再固定所有安全动作 6rem 宽。

### 颜色与内容层

读取本机记录 `output/macos27-20260929-native-audit/native-tokens.json`，确认系统版本及适用外观。以其中强调色、红/绿/橙等语义色为起点，建立填充、图标、可读文字、焦点与选中状态的明确映射，说明有意采用的深色文字变体。禁止只复制一张 hex 表。

主要信息面接近白色，分组中性极浅灰、细分隔；颜色用于操作与状态，减少整行整卡着色、重复徽章、厚边框和层层阴影。没有“Mac 禁用某种色相”的规则；每种非数据颜色都要有角色。保留暖金/浅蓝背景，不靠扩大背景面积遮掩内部未设计。

正文对比度至少 4.5:1，大字及有意义控件边界至少 3:1；禁用态单列可辨识检查，不冒充正常控件对比度通过。检验真实合成背景与状态，不能把低对比的原生亮色直接用作白底小字。

### 材质与弹窗

区分背景、稳定内容、一级分组、局部编辑区、导航控制、菜单、模态外壳及遮罩。每类记录用途、填充、模糊、边界与回退。不是每一层都要透明，不伪造“原生各层固定百分比”。

修复 `brightness(2)` 与背景边界/内部白板叠加造成的断层；移除或调整时用真实背景验证效果，不能把“删掉这条 CSS”本身当验收。正常环境保留可见的真实玻璃透射，同时正文不受背景文字干扰。禁止在弹窗内画假渐变冒充透射，禁止把所有浮层改成实体白板过关。

保留原有遮罩及其强度、滚动锁定、焦点管理、Esc、确认流程和权限。不得照搬原型更轻遮罩。编辑区可以较实，但同角色一致，外壳无突兀白带/亮斑。无滤镜、减少透明度、高对比及减少动态效果有可读回退。

简单表单、长编辑器、信息详情允许适量结构差异；同类标题/正文/底栏一致。明确主要滚动区，低高度、缩放及长内容下关闭和主要操作始终可达；不能依赖固定高度/隐藏溢出来遮掉内容。菜单、色轮和嵌套浮层不被裁切。
