# Runtime repair host tests

Run `./tests/runtime/run_all.sh` from the repository. Requires Apple Command Line Tools (or compatible C compiler), Python 3, Node, and the ESP-IDF cJSON source path used by the individual scripts. Build output is isolated under `/tmp/tianshan-runtime-tests` and `/tmp/tianshan-ssh-host-tests`.

These tests compile production codec, store, SSH, watcher/service and probe sources. Log, engine and synchronous action completion tests extract production function bodies; they do not maintain copies of the algorithms. External FreeRTOS/network/NVS calls are mocked; engine action execution and persistence are separate integration seams, tested independently in their own suites. C tests use ASan/UBSan. The store suite deliberately simulates process death with longjmp; LeakSanitizer is disabled there because abandoned process allocations are intentional, and in the host recovery suite because the reused service registry has process-lifetime allocations. NVS is a failure-injected memory model, not an ESP-IDF power-loss emulator. UI tests execute actual JS functions with a synthetic DOM/API, not a real browser.

SSH host recovery tests execute production storage/import/admission functions and the production service registry. They cover missing-host recovery with historical references, runtime ownership and unknown-state guards, binding-lock serialization, NVS failures/capacity, SD priority/partial merge, concurrent normal-add backup, boot retention, backup/import serialization and list storage error propagation. The copyid suite executes the entire production handler with mocked remote deployment, verification and registration outcomes. Bilingual UI tests cover immediate table refresh, partial results, cache-preserving load failures old-firmware registration confirmation and out-of-order list responses.

Fixtures contain only synthetic credentials/hosts. Nothing here connects to hardware or runs a real model. Test output does not certify ESP32 dual-core timing, FAT/NVS electrical power loss, real libssh2 transport cleanup, browser rendering or resource p95.

Input-repair tests extract the production template write/read/export/JSON persistence functions and the LED filter execution branch. They check zero values, units, legacy defaults, failed edits, NVS/SD loading priority and imported-version replacement using disposable local files. The CSR API suite checks types and byte limits before key access. The copyid quoting suite runs the actual builder's commands only against a disposable local directory and verifies exact public-key bytes. Real browser form roundtrips are part of `npm run test:browser --prefix tests/prompts`; actual CSR signing/parsing is part of `tests/certificate/run_host.sh`.
